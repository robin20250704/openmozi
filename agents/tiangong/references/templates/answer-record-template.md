# 答复记录模板

> 用途：一条实质答复一份记录（可批量攒在 `.creature/tasks/plm-cs-<主题>/answers.md` 里按条目追加）。
> 为什么值得记：`plm-answer-quality.md` 的度量靠它；而"同一个人第三次问同一件事"是**引导缺失**的信号（要做的是补 FAQ，不是第四次耐心解释）。

## 条目格式

```
## ANS-<序号> · <YYYY-MM-DD> · <反馈人/角色>
- 问题（用户原话）: "…"
- 分诊: 用法 / 权限 / 缺陷 / 流程 / 数据 / 已知偏差
- 检索路径: plm-faq.md Q:? → plm-known-deviations.md D-? → plm-module-map.md §?（未命中则写"未命中，转源码核对"）
- 依据等级: 已核实 / 推测 / 未核实
- 依据指针: <文件:章节 / 端点 / 实测单号>
- 答复要点: ① 结论 … ② 操作路径 … ③ 为什么 … ④ 还不行怎么办 …
- 是否追问: 否 / 是（追问了什么 → 说明第 ①/② 段没写清）
- 结果: 用户确认解决 / 转需求 REQ-… / 转升级讨论 / 未回音
- 沉淀: 是否值得晋升为 FAQ 条目（同类第 3 次 ⇒ 是）
```

## 一次会话可能产出多条答复

追问追加、二次澄清、进展汇报都算**新条目**（不要覆盖上一条）——答复链本身就是"这个问题到底问了几次"的证据。

## 晋升规则（回填时顺手判断）

| 条件 | 动作 |
| --- | --- |
| 同类问题 ≥3 次出现 | 晋升为 `plm-faq.md` 条目（L2 整理时做） |
| 答复被用户/实测推翻 | **立即**改写该 FAQ 条目的依据等级与答复，并写 `plm-lessons.md` |
| 同一用户 ≥3 次问同类问题 | 不是用户问题 ⇒ 触发洞察线（很可能是引导/文档缺失，成为一条体验需求） |
| 答复里出现了"我推测" | 记入 `plm-answer-quality.md`；后续若被证实/推翻，回填结论（这是可信度门的校准数据） |
