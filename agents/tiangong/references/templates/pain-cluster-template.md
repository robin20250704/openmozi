# 痛点主题簇模板

> 用途：**洞察线的核心产物**。一个簇 = "同一模块 × 同一作业环节 × 同一现象"的一组反馈。
> 为什么需要它：登记粒度是"一条需求一个可验收的变化"。若把 N 次同类反馈登记成 N 条，backlog 会被同一问题淹没、分析人无法排序、真实的长尾问题被挤掉；而反过来，**N 次反馈正是这条需求最有力的强度证据**（用户自己说不出"有多少人也遇到"，只有客服知道）。

## 簇头

| 项 | 值 |
| --- | --- |
| 簇 ID | `PC-<序号>` |
| 簇标题 | `<模块> × <作业环节> × <现象>`（例：`BOM 编辑器 × 改用量 × 保存后视图顺序变化`） |
| 首次反馈 / 最近反馈 | |
| 累计次数 | N |
| 覆盖角色 | （≥2 个不同角色 ⇒ 不是个人习惯问题） |
| 是否造成实际损失 | 无 / 有一次具体损失（返工/数据错/合规风险） |
| 现有绕法 | 无 / 有（代价：…） |
| 状态 | 观察中 / 已成需求 / 已答复（已知偏差） / 已排除 |
| 代表条目 | `REQ-…` / 无 |
