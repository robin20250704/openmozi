# 目录文件清单标准树（inventory）

> 表头固定为 `| ID | 路径 | 用途 | 写者 | 入口 | → 权威树 |`。
> 本树是**说明层的登记处**——项目里每个值得留存的目录 / 文档在这里有一行。
> **只新增文件，不改 `docs/` 下任何既有文件，不碰 `.creature\`。**

## ① 这棵树回答什么问题

回答"**这个仓库有什么、谁写、什么时候读、去哪儿找权威说法**"：

1. 我要改某个东西，它**在哪个目录**、**唯一写者是谁**（我会不会踩到别的写者）？
2. 这个目录是**干什么用的**、从哪个文件进门？
3. 某个目录里的事实，**权威声明在哪棵标准树**上（还是它只是一份说明）？
4. 某个文档**存不存在**——还是我以为它存在？

**不回答**：接口签名 → `interfaces`；术语与实体 → `ontology`；业务规则 → `business-rules`。

## ③ 写入与冲突纪律

1. **新增目录 / 文档必须登记到本树**；登记项与实际文件不一致时，**以实际为准并修本树**（清单永远服从盘上事实）。
2. **「→ 权威树」列不许为空**：该目录 / 文档承载的事实归哪棵标准树就写它的 ID（如 `interfaces:I-011`）；**确实不成体系才写 `—`**。
3. **写者用角色词**：`人` / `agent` / `生成器` / `外部系统` / `CI`。写"唯一写者"是为了在动手前就知道会不会撞车。
4. **路径必须真实存在**，登记前核实；路径写 `docs/plm-tech/xxx.md` 这种从仓库根起的相对路径。
5. **用途栏要写实际用途**，不要写目录名的同义反复（"设计文档"不是用途，"评审门次与结论口径的定义"才是）。
6. **「→ 指针」列 = 机械可核对的落点**（2026-10-05 新增，口径要说清才有意义）：
   · 本树的「事实」是**路径本身存在**，所以 `def:同指针` 的目标就是那个路径，`selfcheck` 逐条 `fs.existsSync`。
   · **散文条目（`.md`/`.txt`）指向其所在目录**，文件名留在「入口」列。理由：`selfcheck.cjs` L455/L560 把指向
     `.md/.txt/.rst/.mdx` 的 `def:` 判为 `defDoc` 不合格；而写 `TODO` 会让「定义点待补」凭空 +34，
     **把已收敛的债说成新欠的债**。指向目录是真话：目录存在可机械核对。
   · **代价（明写，不藏）**：机械断言**只到目录级**，文件级存在性靠人核对「入口」列。
     根目录下没有上级目录可指的散文条目（`README.md`/`CONTRIBUTING.md`/`RELEASING.md`/`OAUTH.md`/`TELEMETRY.md`，共 5 条）
     写 `TODO` —— `TODO` 是**合法且可数**的值，不是漏填。
   · **收敛路径**：一条 `scripts/check-inventory.cjs`（读本树每行 → 断言 `路径` 与 `入口` 在盘上存在）
     写好后，散文条目就能指到文件级；那时这 5 条 `TODO` 也可以一次性清掉。

### 刻意不登记的目录（这一节让"清单没列 = 不存在"的假设不成立）

不登记的原因分两类，**都不代表"这里没有东西"，只代表"这里的东西不归人管"**：

| 目录 | 为什么不登记 |
| --- | --- |
| `target/` | 构建产物，可重建；体积最大（数 GB），登记它只会淹没真清单 |
| `node_modules/`、`.venv/` | 依赖，由包管理器维护，不归项目 |
| `.git/` | VCS 元数据，由 git 维护 |
| `.codegraph/`、`.tmp/`、`.verify/` | 工具缓存 / 临时工作区，随时可删 |
| `raw-req-ref/` | 外部原始素材（需求原文参考），只读、不进交付路径 |
| `images/`（`docs/` 下） | 截图资产，随文档走，不单独登记 |

**读法**：要在这些目录里找东西，直接 glob，**不要来这里找"它为什么没列"**。

## ④ 上限

入口 `README.md` ≤120 行 / ≤6 KB；分片 ≤150 行 / ≤12 KB。超限**按域拆片**（`docs-tree.md` 已接近上限，`plm-tech` 51 篇再增长就该按主题拆）。
