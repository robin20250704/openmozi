## BOM-01 BOM 多级结构新建必须逐级下钻，能力已存在但未用于创建
**分类**：D（操作繁杂） · **严重度**：中 · **域**：BOM编辑

**现象**：建一棵三层 BOM，用户必须「进 A → 把 A 设为当前根 → 才能给 A 建子件 → 再进 A 的子件……」，
每建一级多一次下钻往返。`/boms/tree` 的递归展开能力只用在**查看**，不用在**创建**。

**前端证据**（`BomEditorPage.tsx:257-264`，用户原话与根因均已留档）：
> **问题现场**：用户原话「**目前这个 BOM 编辑器新建 BOM 逻辑很乱，无从下手**」。根因不是能力缺失——
> `/boms/tree` 早就能递归展开（`BomService.tree`），但编辑器只能给**当前根**加子件，
> 于是「先建电子件还是先建整机」这个顺序问题**只能靠用户自己猜**。
>
> 修法是**就地**给出位置感：点某个子件的「在此件下继续建结构」即可把它设为当前根……

`BomEditorPage.tsx:2049`：（它只显示当前根的直接子件），而 `/boms/tree` 早就能递归展开。

**后端证据**：`BomService.tree`（经 `GET /boms/tree`）—— 递归展开能力已实现。

**残余问题**：30 号文 1-A 的面包屑（`BomEditorPage.tsx:261-264`）**缓解了「无从下手」，
但没有消除根因**——写入能力仍只对当前根开放，`:258` 自陈的根因仍然成立。

**建议**：写入路径复用 `/boms/tree` 的层级结构，让用户在任意层级直接建子件
（与现有面包屑共存，不新增第二套导航）。

### 处置（2026-10-05 · D-16）已修
按建议实现，核心动作是**把「正在看哪棵」与「新行挂到谁」拆成两个状态**。

| | 改动前 | 改动后 |
|---|---|---|
| 写入口 | `rootId`（= 正在查看的根，兼作写入父） | `mountId = mountItem?.id ?? rootId`，**默认仍是当前根** |
| 深层写入 | 只能 `drillInto` 换根（整页对象 + 面包屑全换） | 结构树每行就地「＋ 挂到这」，**不换根、不动面包屑** |
| 位置感 | 无（用户只能从面包屑数自己走了几层） | 添加控件前常显「新行挂到：X（树中选中的那一件）」+「改挂当前根」 |

**为什么这不是"第二套导航"**：既有 `⤵ 在此件下继续建结构`（`bom-drill-into`）换的是**查看**目标，
本改动换的是**写入**父；`setMountTarget` 只调 `setMountItem`/`setNewChild`/`setPickedChild`/`setMsg`，
**从不触碰 `setRootId` 与 `setCrumbs`**——这一点是按 C-030「同一动作不得两个执行面」的纪律显式核过的。

**三个不咬人的细节**（都是"不改就会 400 / 会判错"的地方，不是风格选择）：
1. `parentRev` 在有挂载目标时**不声明**。`header` 是当前根的头，照抄就是拿根的版本号去对
   挂载目标的头——正是本节上文记的那个 `BOM_REV_MISMATCH` 的**同一个坑**。
   `BomHeaderService.ensureHeader:217-222` 明写"parentRev 为空不算不一致"，交服务端解析是受支持的。
2. 锁定判据取**该节点自己**的 BOM 头态（`BomNode.structureState`），不是当前根的 `structureLocked`。
   混用会判反：根是草案、子件已冻结时前端会放开而后端拒之 ⇒ 行级按钮按 `structureState==='RELEASED'` 置灰。
3. 自引用校验改判 `mountId`（写入父）而非 `rootId`，且在挂了载目标时换一句主语正确的话。

**证明**：`npm run typecheck`（`tsc --noEmit`）EXIT=0；`npm run build` EXIT=0；
另按 D-13 对三个可证伪性质做了定向核对（写入读 `mountId`、挂载时 `parentRev` 不声明、
`setMountTarget` 不碰根与面包屑），三条均成立。

**未做（证据边界，明写不掩饰）**：没有跑浏览器端到端断言（仓内无自动化 UI 套件），
故「点行 → 高亮 → 挂载 → 加子件 → 树里出现」这条链目前**只有静态证据**。
这与 D-13「新约束必须配正向探针」的精神一致：本条尚缺一条正向 UI 探针。
