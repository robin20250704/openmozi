## 一、写入与冲突纪律（11 条）

1. **每条声明必须有非空指针** `→ 路径#符号或节标题`。空指针 = 事实没有落处 = 不合格。
   （指针列还兼任 `def:同指针` 的解析目标——写它就意味着"**定义点就是这里**"，所以它必须指向代码，不能指向散文。）
2. **`性质` 决定冲突时谁赢**（这两列存在的全部理由）：
   · `as-built` ⇒ **代码是事实**：代码改了、声明没跟上 ⇒ **树过期，改树**；
   · `contract` ⇒ **树是承诺**：代码与声明不符 ⇒ **代码是缺陷，改代码**。
   所以"接口以代码为准"这句话**只对 `as-built` 成立**——把它当成通用规则，冲突时就无法裁决，
   那正是"一句话两个权威"的来源。
3. **`保证` 是"谁保证一致"**：`def:…` = 值的唯一定义点在代码里哪一处；`assert: <路径>::<用例>` = 有一处机械断言兜着
   （**允许"一份代码在不同部署单元里各存一份"，前提是有一处断言它们相等**）；`gen:…` = 由生成器产出；
   `TODO` = 已声明要补、还没补（**合法**，但要能被数出来）。
4. **拿不准的字段写 `未声明`，不要猜。** 猜出来的"鉴权方式"比空白危险得多。
5. **禁止造接口，也禁止造 `def:` / `assert:`**：指针指不到、代码里查不到的，不写；**断言还没有就写 `TODO`，不要编一个测试名**
   —— **假 def 不可数，TODO 可数**，而可数才谈得上收敛。宁可少写一条，不可写错一条。
6. **一行一个接口**；一行里出现"以及/同时还"通常意味着该拆两行。
7. **ID 全局唯一**：`I-` 前缀、跨分片连续递增、**删除不复用旧号**。新增只有一条路——**追加到对应分片**。
8. **接口只在本树声明**：别的树要引用就写 ID，不要重复写一遍签名。
9. 分片上限 **≤150 行 / ≤12 KB**；入口 `README.md` ≤120 行 / ≤6 KB。超限**按域拆片或拆文件**，不是把行写短。
10. **动过的分片就整片补齐**：没有 `性质` / `保证` 两列的分片，一旦被修改（`selfcheck` 按 mtime 判定），
    它的每一行都必须补齐这两列——**断点续传**，不要求一次性补完所有历史分片。
11. 只新增 / 只改正；改动既有说明层文档不属本树权限。

## 三、76 条 `contract` 声明全是 `assert: TODO`

**这是什么**：本树对外声明了 76 条线路稳定性承诺（帧上限 / 协议版本 / 帧信封 / 请求面 / 事件面 / 错误码），
**却没有任何一处机械断言兜着**。这不是"补两列"的收尾问题，而是一条被这两列**第一次显式说出来的债**。

**收敛路径是具体的一条**：一份 **golden NDJSON 夹具**——把一次完整会话的请求/回帧序列固化成样本，
跑真实桥接进程比对——可以**一次性**覆盖 I-011~I-080。写好之后把这 76 行的 `assert:` 指向它即可。
**一个 `assert:` 被多行引用是正常的**（一个测试守一整面），不算重复声明：重复声明指的是"同一事实写了两条"。

**为什么本轮不写**：2026-10-05 第一轮用户裁定「本轮不写 golden NDJSON 夹具」。`TODO` 是**合法且可数**的值——
假 def 不可数，TODO 可数，而可数才谈得上收敛。

| 断言状态 | 条数 | 说明 |
| --- | --- | --- |
| `assert: TODO` | 76 | I-005~I-080 —— 待一份 golden 夹具一次覆盖 |
| `assert:` 已落地（常驻套件） | 4 | I-083（部署态只认 oidc）/ I-085（白名单闭集）/ I-092 / I-093 → `ipd/deploy/wsl/plm-app/plm-b33-security-verify.py` |

## 四、两条踩过的坑（写给下一个作者）

1. **引用一个不存在的权威，比不引用更危险。** 本树的 README 曾写「口径见 `creature-标准树编写规范.md` §3」，
   而该文件在仓库与技能 references 里**都不存在**（2026-10-05 机械核实）。读者会以为"细则是有的，我照做就行"。
   真实出处只有两处：`../README.md` §"怎么读" 第 5 条 + `.creature/tools/selfcheck.cjs` 的 `SAT_*` 常量。
2. **扫描脚本必须认 Markdown 的 `\|` 转义。** 2026-10-05 第三轮，一份扫描脚本因为没认它，
   报出"2 个分片列数混杂 + 3 条死指针"——独立复核后**全是假告警**（脚本错位读了相邻单元格）。
   **假告警和最危险的缺陷长得很像**：都带着看起来对得上的定位与数字。
   判据：报出问题后，**先用另一条独立路径复核那一条**，再决定改不改文档
   （本次用的是 `.creature/tasks/plm-reverse-engineering-complete/verify-pointers.cjs`）。
