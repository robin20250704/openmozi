# 业务规则标准树（business-rules）

> 表头固定为 `| ID | 条件 → 判定 | 例外 | 违反后果 | → 指针 |`。两列口径见 `../README.md` §"怎么读" 第 5 条与 `.creature/tools/selfcheck.cjs` 的 `SAT_*` 常量。
> **本轮只新增文件**，不改 `docs/` 下任何既有文件，不碰 `.creature\`。

## ① 这棵树回答什么问题

回答"**这条业务规则到底成不成立、由谁拦、违反了会怎样、去哪儿核实**"。

每条声明都是一个可判定的断言（能写成测试），不是散文。回答四类问题：

1. 某个业务动作**被不允许**时，系统返回什么（错误码 / HTTP 状态 / 拒绝文案）？
2. 某个状态迁移、跨单据约束、数值门槛**由哪段代码强制**？
3. 某条规则**只是文档声明**，代码里尚未校验？
4. 散落在 130 篇文档里的规则表述，**哪一份是权威**？

**不回答**（属于别的树）：接口签名与路由 → `interfaces`；术语/实体/状态机定义 → `ontology`；目录用途与写者 → `inventory`。

## ③ 写入与冲突纪律

1. **每条规则必须有指针**，指针列不允许为空。空指针 = 事实没有落处 = 不合格。
2. **业务规则以本树为准。** `docs/plm-*` 下的散文与本树冲突时，以本树为准；散文只作解释层，不作裁判。
3. **证据分级**：
   - `有代码校验` — 规则在 `ipd/plm-app/backend/src/main/java/**` 有可执行的 `throw new BizException` / 拒绝分支。
   - `（文档声明，未见代码校验）` — 只在文档里写成规则，代码中未找到对应实现。**不得据此改动生产代码。**
4. **禁止造规则。** 指针指不到、代码查不到 ⇒ 不写。宁可少一条，不可写错一条——错误的声明会被当裁判用。
5. **禁止重复声明。** 接口只在 `interfaces`，术语只在 `ontology`；本树只声明"条件 → 判定"，别的树要引用写 ID（如 `（见 I-034）`）。
6. **禁止复制散文。** 每行 ≤200 字符；详细解释留在指针指向的既有文档。
7. **违反后果必须写清。** 写不出来写 `未声明`；例外写不出来写 `无`。不允许留空猜测。
8. **新增规则的门槛**：会被 ≥2 个不同任务用到，或错了会出事（数据错误 / 对外承诺违约）。
9. **ID 全局唯一**，`R-001` 起递增，跨分片不复用。删除规则时**不复用旧号**。
