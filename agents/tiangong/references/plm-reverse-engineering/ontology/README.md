# PLM 本体模型标准树（Ontology Standard Authority Tree）

> 本树是 **声明层**：只回答"这个词是什么、这个对象有哪些字段、这个流程有哪些状态、这条断言成不成立"。
> 怎么用、为什么这么设计、背景与教程**不在本树**，留在指针指向的既有文档里。

---

## 1. 这棵树回答什么问题

一句话：**同一个词在项目里到底指哪一个东西，且答案只有一个出处。**

| 类型 | 回答的问题 | ID 前缀 |
| --- | --- | --- |
| 术语 | 这个词/这套缩写在 PLM 里指什么（业务对象名、角色名、结论档、词表取值） | `T-` |
| 实体 | 这个业务对象在库/代码里由哪张表或哪个 struct 承载、关键字段有哪些 | `E-` |
| 状态机 | 这个对象的生命周期有哪些状态、谁在什么条件下从哪到哪 | `S-` |
| 不变量 | 什么条件下某条断言必须成立（"X 存在时 Y 必须成立"） | `V-` |

**为什么要单独一棵**（三条实测理由）：
1. **同一个词在不同文档里含义漂移**。例：阶段推进的"已决策"，DCP 档只认 `GO`/`GO_WITH_RISK`，
   `TERMINATE`/`REDIRECT` **不算通过**；混用两档就会出现"终止/转向被算作已通过"，门被算作已决策、项目被计入在途负载。
2. **同一个词在不同文档里取值集不同**。例：状态机的"状态"在库 CHECK、在 `flows/*.yaml`、在界面常量
   三处各有一份，改一处只改一半即产生"界面能选、服务端不认"的垃圾数据入口。3. **"谁写的"必须唯一**。散落在 130 篇散文档里，任何一次改口径都无法判定"还有哪里没改"；
   收口成带 ID 的树之后，别的树/文档/agent 都只能**引用 ID**，不能各自再声明一份。

**本树不回答什么**（这些在别的树，不要在这里写）：接口签名/路由/错误码 → `interfaces`；
条件 → 判定的业务规则表 → `business-rules`；目录用途/写者/入口 → `inventory`。
需要跨树引用时，在行尾写 `（见 R-012）` 这种 ID 引用，**不在本树重复声明**。

## 3. 写入与冲突纪律

1. **指针不许为空**，且必须是**完整相对路径**（`ipd/…/Foo.java#符号`）——裸文件名（`Foo.java#X`）解析不出定义点，
   而 `保证 = def:同指针` 会把它当**受检定义点**（2026-10-05 实测 23 条因此整片不合格，已全部补成完整路径）。指不到 ⇒ 不要写这一条。
2. **禁止造事实**。写之前用 `grep`/`read` 核实实体名、字段名、状态取值**真实存在**。宁可少写一条，不可写错一条
   —— **错误的定义会被当裁判用，危险高于缺失**。
3. **以代码为真身**。字段、状态取值以**代码里的 struct/表结构/词表常量**为准；术语与不变量的**语义**以文档为准。
   不一致时**以代码为准**，并在该行行尾注明分歧点。
4. **拿不准写 `未声明`**，不要猜。
5. **一行一条事实，每行 ≤200 字符**。禁止把大段散文复制进树里；详细解释留在指针指向的既有文档。
6. **ID 规则**：`T-`/`E-`/`S-`/`V-` 各自主序内递增；删除条目后**不复用旧号**（旧号永久作废）。
7. **冲突裁定**：术语 / 实体 / 状态机 / 不变量以**本树为准**；散文档冲突时以本树为准并回头修散文档（另开改动）。
8. **不跨树重复声明**。同一事实只在它该在的那棵树里声明一次，别的树引用 ID。
9. **分片上限**：每个分片 **≤150 行且 ≤12 288 B**；本 `README.md` **≤120 行且 ≤6 144 B**
   （口径 = `.creature/tools/selfcheck.cjs` L437 的 `SAT_SHARD_BYTES`/`SAT_HEAD_BYTES`，不是散文里另写的数）。
   切分按**业务域**，不按字母序、不按"每片固定 N 条"。
