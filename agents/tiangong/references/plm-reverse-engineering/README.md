## 怎么读（这一节是纪律，不是介绍）

1. **每棵树先读入口 `README.md`**——它是分片地图，也是**常驻上下文那一份**（`context` 每会话投影它）。
   分片**只列规模不列章节**：看某条声明**按 ID 取那一行**，不要整读分片。
2. **`README.md` 一屏读完**（≤120 行 / ≤6 KB）。读不完说明该拆片了——**拆的是文件，不是把字写短**。
3. **冲突以本目录为准**：`.creature/kb/` 里同源内容是**副本**，副本与本目录冲突是"认知冲突"不是"冗余"——
   `context` 已把标准树排在 kb 摘要**之前**，真身先被读到。
4. **指针不是装饰**：每条声明末尾 `→ 路径#节` 指向说明层或代码。**空指针 = 事实没有落处 = 不合格**。
   说明层的散文只能引用声明 ID（如 `（见 R-012）`），**不得引入未声明的新事实**。
5. **`性质` / `保证` 两列回答"谁是权威、谁保证一致"**：
   `性质` ∈ {`contract` 树是承诺、代码必须服从 | `as-built` 树是描述、代码是事实 | `planned` 尚无实现}；
   `保证` ∈ {`def:同指针` / `def:<路径>#<符号>` / `assert:<路径>::<用例>` / `gen:<路径>` / `TODO`}。
   **口径一句话：允许重复，禁止"无断言的重复"。** 同一事实在多个部署单元里各存一份（后端常量 / 前端常量 / 配置 /
   i18n / SDK）本身不是病，**两份都能各自改且没人检查它们是否相等**才是病——`contract` 行的 `assert:` 就是那个报警器。
   `TODO` 是**合法值**：它表示"已声明要补、还没补"，能被数出来；**假 def 不可数**。
6. **本树的主体不止一个**：`interfaces` 里 I-001~I-080 是 **jcode Harness 协议**（真身=手写 Rust），
   I-081~I-095 是 **PLM 应用 HTTP**（真身=运行中生成的 OpenAPI）。看声明先确认讲的是哪个系统。

## 写入纪律

| 谁 | 写什么 |
| --- | --- |
| 工作技能（做交付时） | 改了接口/规则/术语/目录 ⇒ **当场**更新对应树的声明行；改说明层散文 ⇒ 同步指针目标 |
| 信息维护技能 | 不写本目录（它管的是 `.creature/` 侧的经验与淘汰） |
| 元技能 | 只写 `layout.json` 声明（`root:"."` + `ctx:"outline"` + `sat:true`），不写正文 |

- **只新增/只改正**：删一条声明前先确认没有别的文档在用它的 ID。
- **禁止造事实**：指针指不到、代码里查不到的，不写。**错误的声明比缺失的声明危险，因为它会被当裁判用。**
- **禁止引用不存在的权威**（2026-10-05 实测踩过）：三份 README 曾写「口径见 `creature-标准树编写规范.md`」，
  该文件在仓库与技能 references 里**都不存在**。**引用不存在的权威比不引用更危险**——读者会以为"细则是有的，我照做"。
  真实出处只有两处：本节 + `selfcheck.cjs` 的 `SAT_*`。
- 一行一条事实；ID 全局唯一、删除不复用旧号。
