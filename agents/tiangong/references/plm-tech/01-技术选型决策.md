# 01 · AI 原生 PLM 系统 —— 技术选型决策

> 定位：将 `docs/plm-design/05-技术架构设计.md` 的 10 项 ADR 落实为**具体技术栈、版本锁定、选型理由、PoC 验证清单**。
> 原则：每个选型决策可追溯到 ADR + 业务规则 BR + 用户旅程 J + 性能 SLO。

> **实现栈对齐（2026-09-05，S0）**：本文档的选型表描述的是**目标/演进形态**（Spring Boot 微服务 ×12 + K8s+Helm）。实际实施（`.creature/tasks/plm-implementation/`）在保留本选型原则（PG JSONB、Keycloak OIDC、AG Grid、hypersistence JsonType、审计链/发号）的前提下，**本阶段落地为「Spring Boot 3.3 模块化单体 + React 18 + AG Grid + Keycloak OIDC，部署于 WSL docker compose」**，并在以下项与本文档做差异化取舍：
> - **后端**：模块化单体（按聚合分包，演进拆微服务），单库 schema——✅ 保留 ADR-1 的 PG JSONB + ADR-6 的元数据思路（req_type 暂时硬编码，待 S7 元数据化），✅ 复用审计链（V-027 规范）/发号/LogicalId 公共组件；
> - **K8s/Helm/Patroni/ArgoCD**：**推迟**为部署演进目标，当前 WSL compose 满足开发测试（环境未装 helm/无集群）；
> - **AG Grid**：Community 已接入（S1），SSRM/Univer/树形留 P2（见 `phase-plan.md`）；
> - **AI 层（DSH Agent + RAG + 六铁律）**：待 S6，MCP 工具网关骨架已就绪（`plm-service-adapter`）。
> 差异与复用机会详见 `.creature/tasks/plm-implementation/design-inconsistencies.md`；分期计划见 `phase-plan.md`；本文档的 PoC 清单（PoC-1~10）仍作为各能力引入前的验证门。

## 2. ADR 逐项深化

### ADR-1：存储模型 — PostgreSQL 关系列 + JSONB 混合

**选型**：PostgreSQL 16+

**关键决策**：
- 主干字段（`xxx_id`、`status`、`rev`、`class_id`）= 真实列 + 真实外键
- 差异属性 = `attrs JSONB`，按 `T_ATTR_TEMPLATE` 挂载
- **红线**：关联字段坚决不进 JSONB，JSONB 只放属性不放关系

**JSONB 性能三件套**（设计文档 §2.2）：
1. GIN 索引（`jsonb_path_ops`）——通用包含查询
2. 表达式索引——热点属性 `((attrs->>'field'))`
3. 生成列——超阈值属性"转正"为存储生成列 + 普通索引

**版本锁定理由**：PG 16 增强 JSONB 路径查询（`JSONB_PATH_EXISTS`）、并行 VACUUM、逻辑复制改进；Apache AGE 1.5+ 要求 PG 16。

**PoC 验证**：
- [ ] 100 万物料行，JSONB GIN 索引查询 P95 < 100ms
- [ ] 属性转正（生成列）后查询性能提升 ≥ 10x
- [ ] 递归 CTE 10 层 BOM where-used，10 万节点 P95 < 3s

### ADR-2：查询模型 — CQRS 文档事实源 + 索引衍生物

**选型**：PG 直查（主）+ Elasticsearch（全文/聚合）+ Apache AGE（图投影，按需）

**分阶段引入**：
- **Phase 1**：仅 PG（JSONB + 递归 CTE + GIN 索引），满足精确过滤+分页+10 层 BOM
- **Phase 2**：引入 ES（全文检索、跨字段模糊、聚合报表），CDC 投影
- **Phase 3**：引入 Apache AGE（RTM 追溯矩阵、where-used 深层递归），一库多模

**投影纪律**：
- 事实源 = PG；投影可重建
- 接受秒级最终一致（PLM 无毫秒级一致性需求）
- 检索结果必须经权限过滤（先 ACL 过滤后返回）
- ES 投影延迟 P95 < 3s

### ADR-3：约束模型 — 双轨制

**选型**：数据库外键（轨一）+ T_REFERENCE 动态引用注册表（轨二）+ 校验服务

**轨一**：主干对象引用——真实列 + 真实外键 + RESTRICT
**轨二**：企业自定义动态引用——T_REFERENCE + 应用层校验 + 行锁 + 每日对账

**代价声明**：轨二 0.1% 理论并发风险 → 行锁 + 对账补偿换 100% 灵活性

### ADR-4：版本模型 — 修订 + 基线 + 沙箱

**选型**：自研版本管理（不引 Dolt/TerminusDB）

**理由**：
- 修订 90% + 基线 9% + 沙箱 1% 覆盖全场景
- BOM 语义合并不可自动化（医疗行业每次合并须人签字）
- Git 哲学取不可变历史 + 廉价快照；自由分支不可取

### ADR-5：历史与审计 — 事件溯源 + WORM

**选型**：自研 Event Sourcing（T_EVENT + T_AUDIT_LOG + T_AI_TRACE）

**关键设计**：
- 当前状态 = 事件折叠结果
- 历史状态 = 折叠到任意时点
- 对象结构演进后旧事件原样保留，无需迁移
- WORM 存储：审计日志只增不改，哈希链防篡改
- Part 11 合规白送

### ADR-6：扩展机制 — 元数据驱动

**选型**：T_OBJ_TYPE + T_ATTR_TEMPLATE + T_LIFECYCLE + T_WF_TEMPLATE = 配置即数据

**详见**：[03-元数据驱动架构方案](03-元数据驱动架构方案.md)

**核心闭环**：
```
后端 T_ATTR_TEMPLATE 配置 → API 下发列定义 → 前端 AG Grid 动态生成列
                         → API 下发校验规则 → 前端动态校验 + 后端 JSON Schema 校验
                         → 审计自动记录（cell 坐标 = obj_id + rev + attr_code）
```

### ADR-8：AI 架构 — Agent + RAG + 工具网关 + 可信治理

**选型**：基于 **DeepSeek Harness（DSH）** 的 Agent 编排框架

**详见**：[04-AI-Agent融入方案](04-AI-Agent融入方案.md)

**核心架构**：
```
DeepSeek Harness（Agent 编排）
  ├── 工具网关（查询/计算/文档生成/Resolver，经权限服务穿透用户身份）
  ├── RAG 知识库（pgvector + 产品知识图谱 + 法规标准库 + 历史库）
  ├── 模型管理（DeepSeek V3/R1 + vLLM 私有化推理，版本入配置管理）
  └── AI 审计（T_AI_TRACE：模型版本/prompt hash/上下文/采纳）
```

**六条铁律**（BR-20 落地）：
1. AI 永远不是签署人 → 产出 = AI_GENERATED 状态建议对象
2. AI 审计追踪 → T_AI_TRACE 全量记录
3. 无引用不回答 → RAG 强制引用 + Resolver 验证
4. 确定性封装 → 合规判定 = LLM 理解 + 确定性规则引擎裁决（温度=0）
5. 权限先于智能 → 全程携带用户身份，先 ACL 过滤后检索
6. AI 功能验证 → GAMP5/CSA：冻结版本、定义预期用途、漂移监控

### ADR-9：集成机制 — Outbox + CDC 事件驱动

**选型**：Kafka 3.7 + Debezium 2.7 + Outbox 模式

**纪律**：
- 生产者一律 Outbox（业务写入与事件落库同事务）
- 禁双写（不"写库再调接口"）
- 消费者幂等（事件 ID 去重表）
- 死信队列 + 重放工具
- 接口契约带 eco_code（跨系统审计链）

### ADR-10：部署 — 私有化 K8s + 验证/生产双环境

**选型**：K8s 1.30 + Helm + ArgoCD（GitOps）

**部署架构**：
```
企业数据中心（私有化 K8s）
  ├── 接入：Ingress/WAF → API 网关 → SPA 静态资源
  ├── 应用：领域服务×N（HPA）、平台服务×N、AI 服务（GPU 节点池）
  ├── 数据：PG(主从+Patroni)、ES、Redis、MinIO、Kafka
  ├── 运维：Prometheus/Grafana、Loki、OpenTelemetry、pgBackRest
  └── DMZ：供应商门户（独立集群）──零信任网关──→ 内网 API
验证环境：独立命名空间/独立集群，与生产同构低配
```

**决策**：DeepSeek Harness（DSH）作为 AI Agent 编排框架。DSH 原生支持 subagent 并行、workflow 批量编排、ralph fresh-agent 内省；MCP 协议天然适配工具网关；env 身份声明机制满足权限穿透；审计留痕与 T_AI_TRACE 对齐。
