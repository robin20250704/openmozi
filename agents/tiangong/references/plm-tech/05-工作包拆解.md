# 05 · 工作包拆解

> 定位：将设计文档 + 技术选型 + UI 原型拆解为**可分配、可估算、可排期的工作包（WBS）**。
> 输入：`docs/plm-design/` 五份设计文档、`docs/plm-tech/01~04` 技术方案、`docs/plm-ui-prototypes/` 8 模块 + 6 旅程。
> 结构：6 期 × 32 工作包，含依赖关系与工作量估算；执行方式：全部 Agent 开发。

> **实现栈对齐（2026-09-05，S0）**：本文档的 32 工作包 / 6 期（P0~P5）为完整 WBS。实际实施按 `.creature/tasks/plm-implementation/phase-plan.md` 的 **S0-S8 分期**推进（S0 OIDC/文档对齐 + S1 需求/项目域已交付；S2 变更域→S8 CSV 验证）。技术栈差异：以 Spring Boot 模块化单体 + React + AG Grid + WSL compose 落地（本文档假设微服务 + K8s），**工作包内容（业务能力）不变**，仅实现载体与部署形态不同，仍在每期按 WBS 的顺序与依赖推进。

---

## 1. WBS 总览

```
PLM 系统
├── P0 基础设施与平台服务（6 包）          ← 地基
├── P1 核心数据域 + 元数据驱动（6 包）      ← 骨架
├── P2 前端工作台 + Datagrid（5 包）        ← 面子
├── P3 变更流程 + 阶段门 + 集成（6 包）     ← 神经
├── P4 AI Agent 融入 + RAG（5 包）          ← 大脑
└── P5 部署 + CSV 验证 + 试运行（4 包）     ← 交付
```
