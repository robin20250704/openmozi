> 盘点时间：2026-09 · 方法：静态代码分析（160 Java 文件 + 22 Flyway 迁移 + 10 流程 YAML + 前端全量）+ 运行态核查（docker compose ls / docker ps）
> 用途：作为 IPD 扩展重构的"改造前快照"——重构批次的改动图均以本文事实为基线。

## 1. 系统总览：一套代码基座，两条产品线并存

```
ipd/
├── plm-app/          ← 本方案改造对象：AI 原生 PLM（Spring Boot 3.3 + React 18）
│   ├── backend/      com.plm · 模块化单体 · 8 领域包 + 12 平台包 + security/audit/common
│   └── frontend/     plm-web · Vite SPA · 12 页面
├── deploy/wsl/       ← 部署区（4 个 compose 项目）
│   ├── plm-env/dev-infra-plm.yml     plm-infra：PG16+pgvector / Kafka / Keycloak / ES / Debezium / Embedding
│   ├── plm-app/docker-compose.plm-app.yml   plm-app：plm-service(8081) + plm-web(5174)
│   ├── docker-compose.pdm.yml        pdm：pdm-pg / pdm-redis / pdm-minio（pdm-api 当前未运行）
│   └── docker-compose.wsl.yml        wsl：OpenProject 17.7（PMS 角色）
└── mcp/pdm-lite/     ← 早期 PDM-lite（Node.js，已停运；其基础设施被 plm 复用）
```

**运行态（docker ps 实测）**：12 容器在跑——`plm-pg`(5433, healthy)、`plm-keycloak`(8090)、`plm-kafka`(9092, healthy)、`plm-es`(9201, healthy)、`plm-debezium`(8083)、`plm-embedding`(8084)、`plm-service`(8081, healthy)、`plm-web`(5174)、`pdm-pg`(5432)、`pdm-redis`(6379)、`pdm-minio`(9000)、`wsl-backend-1`(OpenProject 8080)。

**关键判断**：基础设施层（Kafka/Debezium/ES/Keycloak/pgvector/Embedding）**已就绪但应用层未接**——后端无 Kafka 客户端、无 Outbox 表、ES 走纯 REST 无 Maven 依赖。这是"基座已建、电缆未接"的状态。

### 2.4 数据模型要点

- 元数据表（T_OBJ_TYPE/T_ATTR_TEMPLATE）**存在且活跃**（V4/V10~V12/V19/V21~V22 持续扩展）；**无 T_LIFECYCLE/T_WF_TEMPLATE**（状态机在 YAML 不在库——与基线 ADR-6 有偏差，作为已知偏差接受）。
- **IPD 扩展所需表全部缺失**：t_charter / t_biz_plan(+rev) / t_market_segment / t_roadmap(+item) / t_review(+item/attendee) / t_open_issue（现 t_gate_issue 为裸表：仅 OPEN/CLOSED，无 due/owner/OVERDUE/证据/门阻断） / t_cbb(+usage/reuse_analysis) / t_pm_mapping / t_termination / t_eol_plan / t_pipeline_snapshot / t_recon_rule / t_recon_run / t_outbox。
- t_project 缺 prj_type / charter_id / biz_plan_id / lpdt_id / pms_project_id / tdp_flag；现以 op_identifier/op_version_id/op_sync 三列承载 OP 映射（V17）——R-03 要求收敛到 T_PM_MAPPING。（注 2026-11-13 批次66：`prj_type` 已随 B1/V23 落地，CHECK 值域 V219 起为 PDP/TDP/PLATFORM/CUSTOM/**PILOT**（试产/Pilot Production）。）
- **t_team 不存在**（现用 t_project_member）——M-08 的 PDT 生命周期（formed_on/disbanded_on）无处安放。
- 签名/审计/事件均为"哈希链 + append-only"，DB 级 WORM 约束（REVOKE UPDATE/DELETE / 触发器）未设。

### 2.5 测试现状

- 仅 2 个 `@SpringBootTest` 集成测试（真实 PG+Flyway）：需求状态机/BR-09 门禁/审计验签/发号/4 方签署；文档+注册域。
- 部署区另有 2 个 node:http 走查脚本（plm-requirement-functional.cjs / plm-s2-e2e.cjs，X-PLM-User 头模拟多角色）。
- **无单元测试、无契约测试、无安全测试**——分批重构需要先把"回归安全网"织出来。

## 4. 部署现状（ipd/deploy/wsl）

### 4.1 网络拓扑（V-030 确认）

```
Windows host ── netsh portproxy ──► WSL2
   ├─ [wsl_default]  OpenProject 8080（PMS 角色）
   └─ [pdm_net]      plm-infra 6 容器 + plm-app 2 容器 + pdm 3 容器（全隔离，互不可见）
        plm-service ──► plm-pg(5433 内部 5432)、plm-keycloak(JWKS)、plm-es、plm-embedding
        plm-service ──► host.docker.internal:8080 → OpenProject（Host 头伪装 localhost；
                        JDK 需 -Djdk.httpclient.allowRestrictedHeaders=host）
```

- plm-infra 已按 `docs/plm-tech/07-环境差距分析.md` 补齐 **G3~G7 全部组件**（pgvector 用 pgvector/pgvector:pg16 预构建镜像；Kafka 3.7 KRaft；Keycloak 25 已建 realm=plm + keycloak 库；ES 8.13 单节点；Debezium 2.7；自研 Rust embedding sidecar 复用 jcode-embedding，中文 MiniLM 384 维）。
- Keycloak 用户迁移脚本（plm-migrate-users.sh）已备；**后端仍默认 dev 认证模式**（PLM_AUTH_MODE=dev）。

### 4.2 OpenProject 侧（PMS 现状）

- 已有 24 个 .rb 配置脚本（用户/OAuth Doorkeeper app/角色/工作流/Wiki/评审门工作包类型）+ webhook 评审门联动规则（PDM_GATE_TYPES=KCPReview,TRReview——注意：这是 pdm-lite 的配置，plm-app 需对等重建）。
- OP 项目 142/144 的模板化是手工脚本完成；**PDP/TDP/PLATFORM/CUSTOM 四类项目模板库未建**。（2026-11-13 批次66：项目类型全集增 `PILOT` 试产项目，模板库口径相应为五类。）
- 集成方式为脚本驱动 + 字段直同步，**无声明式 IaC、无 CI/CD、.env 明文密钥、portproxy 依赖 WSL IP**。
