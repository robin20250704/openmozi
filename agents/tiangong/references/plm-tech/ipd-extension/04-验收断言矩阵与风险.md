# 04 · 验收断言矩阵与红线守护

> 用途：①每批走查的断言来源（谁验收什么）；②设计条款 → 批次 → 断言的端到端追溯（合规门要求"每条规则可追踪到系统实现"）；③风险登记与降级预案。

## 1. 业务规则断言矩阵（IBR-01~14）

| 规则 | 断言（可判定） | 批次 | 走查方式 |
|---|---|---|---|
| IBR-01 DCP/TR 分离 | DCP 结论集合=GO/GO_WITH_RISK/TERMINATE/REDIRECT；TR=PASS/COND/FAIL；TR FAIL 不流转阶段但阻断 DCP 预审；两者 checklist 模板集不相交 | B2 | 走查+DB 断言（conclusion CHECK 约束） |
| IBR-02 BizPlan 受控绑定 | DCP 预审：无 APPROVED 版本 biz_plan_rev → 阻断；评审后 bound_review_id 回填 | B2/B3 | 走查 J-IPD5 步骤1/6 |
| IBR-03 PDP 不含新技术 | PDP 预审出现"新技术识别"提示项 → 引导拆分 TDP（提示不阻断，立项守卫拒绝无 charter 直建） | B8/B3 | 规则触发走查 |
| IBR-04 终止合法结论+资产处置 | TERMINATE → t_termination 必填 asset_disposition（CBB 沉淀/归档/资源释放）→ 核验后才 CLOSED | B9 | 走查 J-IPD9 |
| IBR-05 项目唯一入口 | ProjectController.create 无 charter_id → 403；全量项目 charter_id 非空（对账规则） | B3 | API 正负向 |
| IBR-06 TR2/DCP1 复用检查 | 预审检查项"复用分析已批准"（t_reuse_analysis）缺 → 阻断 | B8 | 走查 J-IPD8 |
| IBR-07 证据制进度 | 交付物 APPROVED 事件 → PMS 任务自动完成判定；手填进度仅参考色 | B5/B11 | 事件链走查 |
| IBR-08 证据包实时投影 | 评审页数据全部来自系统 API（无离线材料入口）；证据包聚合 API 按 gate_code 出数 | B2/B11 | UI 走查 |
| IBR-09 权限随窗口期 | 项目关闭/团队解散/成员退出 → t_user_role 批量 expire（同事务）；越权访问 403 | B10 | 权限走查 |
| IBR-10 TRL 校验 | 引用 CBB 时 trl_level<VERIFIED → 400 阻断 | B8 | API 正负向 |
| IBR-11 管道阈值 | 负载/排队>85% → 预警 + 议程生成事件 | B9 | 构造数据触发 |
| IBR-12 EOL 检查单 | 检查单任一未完成 → 退市生效拒绝 | B9 | 正负向 |
| IBR-13 Charter 演化原子性 | DCP0=GO：冻结+BPL v1.0+PROJECT_APPROVED 同事务；注入②失败→全回滚；Charter 冻结后 update → 403 | B3 | 事务注入测试 |
| IBR-14 遗留问题闭环 | COND → 逐条 t_open_issue；逾期 → OVERDUE+升级通知；绑定门预审未清零 → 阻断 | B2 | 走查+定时任务触发 |

## 5. 风险登记与降级预案

| # | 风险 | 概率 | 影响 | 缓解 | 降级预案（触发即执行） |
|---|---|---|---|---|---|
| R1 | FlowEngine 升级（会签/并行/守卫）波及存量 10 个 YAML 流程回归 | 中 | 高 | 兼容式扩展（无新字段=旧行为）+ B0 冒烟矩阵 | 新引擎仅服务 T_REVIEW 域（review-flow 独立），存量流程不迁移 |
| R2 | OP 侧模板/工作流配置依赖人工脚本，KCP 锁定（R-02）难以强制 | 高 | 高 | 集成专用账号最小授权（仅该账号可关 KCP）+ RCN-03 检出兜底 | 降级为"检出+告警+人工纠正"，R-02 从"技术强制"降为"流程强制+对账"（记录偏差，报用户确认） |

| R4 | 双跑期（t_gate_result ∥ T_REVIEW）数据漂移 | 中 | 中 | 双写由同一事务完成 + 对账规则核对 | 缩短双跑期，以走查代双跑 |
