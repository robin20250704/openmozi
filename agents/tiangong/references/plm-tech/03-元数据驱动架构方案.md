# 03 · 元数据驱动架构方案

> 定位：将 ADR-6（元数据驱动）落实为**可实施的全链路闭环架构**。
> 输入：`docs/plm-design/02-信息架构设计.md` §4.4 元数据基础对象、`05-技术架构设计.md` §10 可扩展性设计。
> 核心命题：**企业差异零代码扩展**——新对象类型/新属性/新流程/新校验规则不改代码，配置即上线。这是 PLM 适配医疗器械行业多品类（呼吸机/制氧机/血糖仪/试剂）差异的核心机制。

> **实现栈对齐（2026-09-05，S0）**：本文档的 T_OBJ_TYPE/T_ATTR_TEMPLATE/T_LIFECYCLE/T_WF_TEMPLATE 全链路闭环为**目标架构（S7 落地）**。S1 需求/项目域先用**显式 schema**（`t_requirement.req_type CHECK`/`t_project` 固定列，属性差异用 JSONB）交付，**req_type 硬编码枚举与本文档「零代码扩展」理念有出入**（已登记 `design-inconsistencies.md` A4）。元数据驱动（列生成/校验/属性转正）安排在 **S7**，届时去掉 CHECK 硬编码，改为 `T_OBJ_TYPE(T_REQ)` 模板驱动（V-008 知识库即配置）。见 `phase-plan.md`。

## 1. 元数据模型总览

### 1.1 五张元数据表（配置即数据）

```
T_OBJ_TYPE        —— 对象类型注册（物料/文档/需求/ECO...）
T_ATTR_TEMPLATE   —— 属性模板（按分类挂载，驱动前端列+后端校验）
T_LIFECYCLE       —— 状态机定义（状态+迁移+守卫）
T_WF_TEMPLATE     —— 流程模板（节点+会签+时限+升级）
T_REFERENCE       —— 动态引用注册（轨二约束）
```

**设计原则**：这五张表本身是配置数据，由系统管理员通过"元数据管理"界面维护；元数据变更本身走变更控制（CSV 要求）。

### 1.2 全链路闭环

```
┌─────────────────────────────────────────────────────────────────┐
│                    元数据驱动全链路闭环                           │
│                                                                  │
│  [配置层] 管理员配置 T_ATTR_TEMPLATE / T_LIFECYCLE / T_WF_TEMPLATE │
│      │                                                           │
│      ▼                                                           │
│  [API 层] 元数据服务下发列定义/校验规则/状态机/流程定义             │
│      │                                                           │
│      ├──→ [前端] AG Grid 列自动生成 + 动态校验 + 状态锁           │
│      ├──→ [后端] JSON Schema 校验 + 状态机守卫 + 流程引擎          │
│      ├──→ [审计] cell 坐标 = {obj_id, rev, attr_code} 自动记录    │
│      ├──→ [AI]   上下文协议 GridContext 含 object_type + attrs    │
│      └──→ [搜索] ES 投影 attrs 平铺 + 热点属性转正               │
│                                                                  │
│  [扩展] 企业加属性 → 配置 T_ATTR_TEMPLATE → 全链路自动生效，零发布  │
└─────────────────────────────────────────────────────────────────┘
```

## 2. 对象类型注册（T_OBJ_TYPE）

### 2.1 表结构

```sql
CREATE TABLE t_obj_type (
    id              BIGINT PRIMARY KEY,
    code            VARCHAR(32) UNIQUE NOT NULL,   -- 'ITEM', 'DOC', 'REQ', 'ECO'
    name            VARCHAR(64) NOT NULL,
    parent_type_id  BIGINT REFERENCES t_obj_type(id),  -- 继承（电子件→物料→对象）
    table_name      VARCHAR(64) NOT NULL,           -- 't_item_rev', 't_doc_rev'
    id_prefix       VARCHAR(16) NOT NULL,           -- 'ITEM', 'DOC', 'ECO'
    lifecycle_id    BIGINT REFERENCES t_lifecycle(id),
    has_version     BOOLEAN DEFAULT TRUE,
    has_baseline    BOOLEAN DEFAULT FALSE,
    ai_agent_enabled BOOLEAN DEFAULT TRUE,          -- 是否启用 AI Agent
    created_on      TIMESTAMPTZ DEFAULT now()
);
```

### 2.2 继承体系

```
OBJECT（基类）
  ├── ITEM（物料）
  │   ├── ITEM_RAW（原材料：材料牌号/规格/ROHS）
  │   ├── ITEM_ELECTRONIC（电子件：封装/MSL/EOL）
  │   ├── ITEM_STRUCTURAL（结构件：材料牌号/模具号）
  │   ├── ITEM_SOFTWARE（软件项：安全分级/SOUP/CRC）
  │   ├── ITEM_PACKAGING（包装：规格/标签/UDI）
  │   ├── ITEM_REAGENT（试剂配方：储存条件/效期，密级=机密）
  │   └── ITEM_PURCHASED（外购成品：供应商注册证）
  ├── DOC（文档）
  ├── REQ（需求：UR/SR/REG/RC）
  ├── ECO（变更）
  └── ...
```

**继承语义**：子类型继承父类型的所有属性模板 + 状态机；子类型可追加特有属性。

## 3. 属性模板（T_ATTR_TEMPLATE）

### 3.1 表结构

```sql
CREATE TABLE t_attr_template (
    id              BIGINT PRIMARY KEY,
    obj_type_id     BIGINT REFERENCES t_obj_type(id),
    class_id        BIGINT REFERENCES t_classification(id),  -- 按分类挂载
    attr_code       VARCHAR(64) NOT NULL,        -- 'msl_level'
    attr_name       VARCHAR(128) NOT NULL,       -- 'MSL 等级'
    data_type       VARCHAR(16) NOT NULL,        -- STRING/INT/DECIMAL/BOOL/DATE/LOV/REF/JSON
    data_source     VARCHAR(16) DEFAULT 'INPUT', -- INPUT/LOV/SCRIPT/INTERFACE
    lov_values      JSONB,                       -- ["1","2","3","4","5a","5b"]
    is_required     BOOLEAN DEFAULT FALSE,
    is_key          BOOLEAN DEFAULT FALSE,       -- 查重关键属性
    is_searchable   BOOLEAN DEFAULT TRUE,        -- 是否入 ES 索引
    uom_id          BIGINT REFERENCES t_uom(id), -- 计量单位
    regex_check     TEXT,                        -- '^[A-Z]{2}-\d{4}$'
    inherit_flag    BOOLEAN DEFAULT TRUE,        -- 子分类继承
    sec_level       VARCHAR(16) DEFAULT 'INTERNAL', -- PUBLIC/INTERNAL/SECRET/CONFIDENTIAL
    default_value   JSONB,                       -- 默认值
    computed_expr   TEXT,                        -- 计算属性表达式（如风险矩阵 S×P）
    display_order   INT,                         -- 列显示顺序
    width           INT DEFAULT 150,             -- 列宽
    frozen          BOOLEAN DEFAULT FALSE,       -- 是否冻结列
    ai_hint         TEXT,                        -- AI 辅助提示
    effective_from  DATE,                        -- 属性生效日期（版本化）
    UNIQUE (obj_type_id, class_id, attr_code)
);
```

### 3.3 属性模板驱动后端校验

**JSON Schema 自动生成**：
```java
// 后端：从 T_ATTR_TEMPLATE 生成 JSON Schema
public JsonSchema buildSchema(Long objTypeId, Long classId) {
    var templates = attrTemplateRepo.findByTypeAndClass(objTypeId, classId);
    var schema = JsonSchema.object();
    for (var t : templates) {
        var prop = schema.property(t.getAttrCode());
        switch (t.getDataType()) {
            case "STRING" -> prop.type("string").pattern(t.getRegexCheck());
            case "INT" -> prop.type("integer");
            case "LOV" -> prop.enum_(t.getLovValues());
            case "BOOL" -> prop.type("boolean");
        }
        if (t.getIsRequired()) prop.required();
    }
    return schema;
}

// 写入校验
public void validate(Long objTypeId, Long classId, JsonNode attrs) {
    var schema = buildSchema(objTypeId, classId);
    var errors = schema.validate(attrs);
    if (!errors.isEmpty()) throw new ValidationException(errors);
}
```

### 3.4 属性"转正"机制（性能自适应）

**设计文档 §2.2**：系统监控 JSONB 属性查询频率，超阈值→管理员一键提升为生成列并建索引。

```sql
-- 监控：查询 pg_stat_user_indexes 找热点 JSONB 路径
SELECT attr_code, query_count
FROM t_attr_usage_stats
WHERE query_count > 10000  -- 阈值
ORDER BY query_count DESC;

-- 转正：生成列 + 索引
ALTER TABLE t_item_rev ADD COLUMN msl_level VARCHAR(8)
    GENERATED ALWAYS AS (attrs->>'msl_level') STORED;
CREATE INDEX idx_item_msl ON t_item_rev(msl_level);

-- 更新元数据标记
UPDATE t_attr_template SET is_promoted = true WHERE attr_code = 'msl_level';
```

**灵活性归灵活性，性能按使用量自适应优化。**

### 4.2 状态机引擎（自研轻量）

```java
public class LifecycleEngine {
    // 执行状态迁移
    public void transition(String objType, Long objId, String action) {
        var obj = repo.findById(objId);
        var lifecycle = lifecycleRepo.findByObjType(objType);
        var transition = findTransition(lifecycle, obj.getStatus(), action);

        // 1. 守卫校验
        for (var guard : transition.getGuards()) {
            if (!guardEvaluator.evaluate(guard, obj)) {
                throw new GuardFailedException(guard.getErrorMessage());
            }
        }

        // 2. 角色校验
        if (transition.getRole() != null) {
            authzService.requireRole(transition.getRole());
        }

        // 3. 状态迁移
        obj.setStatus(transition.getTo());
        repo.save(obj);

        // 4. 事件溯源
        eventService.emit(objId, "STATUS_TRANS",
            Map.of("from", transition.getFrom(), "to", transition.getTo(),
                   "action", action, "by", currentUser(), "at", now()));

        // 5. 触发后续动作（如发布→生成PDF受控版）
        if (transition.getPostAction() != null) {
            actionExecutor.execute(transition.getPostAction(), obj);
        }
    }
}
```

### 4.3 BR 规则到守卫的映射

| BR | 守卫 | 实现位置 |
|---|---|---|
| BR-01 | `checkNotReleased`：已发布禁直接修改 | 写入服务前置校验 |
| BR-02 | `checkNotFrozen`：基线冻结不可变 | 基线服务 |
| BR-03 | `checkNotReferencedByRegBaseline`：被注册基线引用禁作废 | 状态机守卫 |
| BR-04 | `checkEsign+checkSignScope`：电子签名+授权范围 | 签名服务 |
| BR-07 | `checkChildrenReleased`：BOM 子件全已发布 | BOM 与基线域 |
| BR-09 | `checkChecklistComplete`：阶段门 checklist 100% | 项目域服务 |

## 6. 零代码扩展机制

### 6.1 新增对象类型

```
管理员 → 元数据管理界面 → 注册 T_OBJ_TYPE（如"试剂批记录"）
  → 绑定 T_ATTR_TEMPLATE（批号/效期/储存条件/检验结果）
  → 绑定 T_LIFECYCLE（生产→检验→放行→使用→过期）
  → 绑定 T_WF_TEMPLATE（批放行流程）
  → 自动生效：
    - API 自动生成 CRUD 端点
    - 前端网格自动生成列
    - 校验自动生效
    - 审计自动记录
    - AI Agent 自动可用
```

### 6.2 新增属性

```
管理员 → 属性模板管理 → 新增 T_ATTR_TEMPLATE（如"酶配方版本"）
  → 前端：物料库网格自动多出列（零发布）
  → 后端：JSON Schema 自动更新校验
  → 审计：cell 坐标自动包含新属性
  → 搜索：ES 投影自动包含（is_searchable=true）
  → 性能：查询频率超阈值后提示转正
```

### 6.3 新增校验规则

```sql
-- 规则引擎脚本化（受限 DSL）
INSERT INTO t_validation_rule (obj_type, attr_code, rule_expr, error_msg, grayscale)
VALUES ('ITEM', 'patient_contact', 
        'patient_contact == true AND bio_compat_report_id IS NULL',
        '患者接触件必须关联生物相容性评估（BR-15）',
        true);
```

**灰度生效**：新规则先以"告警"模式运行（不阻断写入，仅提示），验证无误后切换为"阻断"模式。

### 6.4 新增流程

```
管理员 → 流程模板管理 → 配置 T_WF_TEMPLATE（如"紧急变更通道"）
  → 绑定到 ECO 状态机的条件分支
  → 流程引擎自动加载执行
  → 不改流程引擎代码
```

## 7. 元数据变更治理（CSV 合规）

**关键约束**：元数据本身是配置项，变更须走变更控制。

```
元数据变更请求
  → 评估影响范围（哪些对象类型/属性/流程受影响）
  → 验证环境先生效 → 测试验证
  → CCB 审批（如新增必填属性会影响存量数据）
  → 生产环境生效
  → 审计记录（元数据变更也是审计事件）
```

**存量数据兼容**：
- 新增必填属性 → 存量数据标记"待补全"，不阻断读取
- 删除属性 → 软删除（is_deleted=1），不物理删除，历史审计可查
- 修改 LOV → 只增不删（删除选项须确认无引用）

## 9. 性能保障

| 关注点 | 机制 |
|---|---|
| 元数据查询频率高 | Redis 缓存（T_ATTR_TEMPLATE/T_LIFECYCLE/T_WF_TEMPLATE）；变更广播失效 |
| JSONB 查询性能 | GIN 索引 + 表达式索引 + 属性转正 |
| 状态机判定性能 | 状态机定义缓存；守卫判定走缓存权限 |
| 流程引擎性能 | 流程定义缓存；无状态执行；状态存库 |
| 元数据变更影响 | 灰度生效；存量数据兼容；变更评估工具 |
