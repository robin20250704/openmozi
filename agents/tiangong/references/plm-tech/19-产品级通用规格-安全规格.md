# 产品级通用规格：安全规格（认证 / 授权 / 凭据 / 供应链 / 暴露面 / 回归门禁）

> **效力**：本文件是**产品级规格**——描述「PLM 产品要求**所有域、所有批次**怎么实现安全」，
> 与 12/13/14/16/17/18 号文同级。模块文档（05 §11、08/09/10 等）描述「当前怎么实现」；
> 与本文冲突时以本文为准，实现细节以代码与部署配置为准。
> **新域/新批次接入必须照抄本文的判据**（见 §7 检查表），不允许「参照现有实现即可」。
>
> **覆盖范围（溯源）**：主证据来自 **批次33 安全审视的两轮加固**——
> **第一轮**＝低耦合补丁（Tomcat / pgjdbc / Spring Framework / Spring Security 同线 + Keycloak 25.0 → 26.6.4）+
> dev 认证旁路收口 + 免认证面收口 + 登录安全策略落地；
> **第二轮**＝跨大版本（Spring Boot 3.3.5 → 3.5.16，连带 Hibernate 6.6.53 / Framework 6.2.19 / Security 6.5.11 /
> Flyway 11.7.2 / Jackson 2.21.4 / kafka-clients 3.9.2）+ 构建通道自愈。
> 同族规格另吸收了批次31/32 已被运行态验证的安全相关修法（错误契约脱敏、审计链 WORM、边级角色门、下载票据）。
> 全部结论均有**运行态实测**，逐条证据指针见 §6；本报告的完整验收材料在
> `.creature/tasks/plm-b33-security-review/acceptance-report.md`。

## 1. 六条不变量（先读这六条，其余是它的展开）

| # | 不变量 | 一句话 |
| --- | --- | --- |
| INV-1 | **默认拒绝** | 没有明确放开的，一律需要认证；安全配置里"多一条豁免"必须能被 CI 抓到 |
| INV-2 | **兜底值就是安全默认** | 任何 `:-dev` / `admin` / `*` 形式的兜底都是一次潜在事故（L-179 同型） |

| INV-4 | **判据必须打在"行为"上，不是"配置写了"** | 策略生效=正确凭据也被拒；端点认证=无凭据实打；版本达标=解析后的实际版本 |
| INV-5 | **安全结论必须带覆盖边界** | 没说清"没扫到什么"的"已无高危"，等于没说 |
| INV-6 | **升级必须可回滚、可诊断** | 有状态组件先备份；环境问题不得伪装成产品缺陷（离线构建、颜色码、解析口径） |

## 2. 规格总览（G-SEC-1 ~ G-SEC-24）

> 每条＝规格陈述 + 为什么 + 落地形态 + 回归判据。判据列里的套件/脚本均为仓库内可复跑资产。

### A. 认证姿态（G-SEC-1 ~ 3）

| ID | 规格 | 为什么 | 落地形态 | 回归判据 |
| --- | --- | --- | --- | --- |
| **G-SEC-1** | **除登录/身份提供方回调外，一切端点默认需要认证**；免认证集合必须是**闭集**且逐条写明理由与代价 | 每一条豁免都是永久降低一处保护；散着加、只在提交信息里解释，等于豁免面随批次悄悄扩大 | `SecurityConfig.filterChain` 单点集中 `permitAll`，每条上方写理由与代价 | `T3-14 §S2.7` 静态解析白名单并与登记集合**逐字比对**（多/漏一条即红）；`§S2` 全量端点无凭据扫描必须 0 违规 |
| **G-SEC-2** | **认证模式的兜底值必须是安全侧**（容器路径 `oidc`）；`dev` 只能显式开启 | 兜底 `dev` 意味着"忘了传环境变量"就等于关闭认证 | `docker-compose.plm-app.yml: PLM_AUTH_MODE: ${PLM_AUTH_MODE:-oidc}`；`application.yml` 的 `:dev` 只服务宿主直跑开发（注释写明分工） | `T3-14 §S1` 断言 compose 兜底为 `oidc`、运行实例 `PLM_AUTH_MODE=oidc` |
| **G-SEC-3** | **dev 身份旁路（`X-PLM-User`）必须运行时可控、默认关、客户端头随开关发送**；重新打开＝改配置 + 重启（**不需要重新出产物**） | 旁路绕过全部权限校验；构建期常量会让"重新打开"变成"重新发布" | 前端运行时配置：nginx entrypoint 注入 `/plm-config.js` → `window.__PLM_CONFIG__.devLogin`（三级取值：容器注入 > `import.meta.env.DEV` > 关闭）；`api/client.ts` 仅在开关打开时带 `X-PLM-User` | `T3-14 §S1`（`/plm-config.js` 不含 `devLogin:true`、dev 头取数 401）；`W27`（真浏览器：无「进入（dev）」、有显式停用说明、SSO 路径仍可达） |

**配套（"功能保留"的证明方式）**：旁路被关闭后，必须能用**一次性取证**证明它还能被打开（否则"关闭"与"删掉"无法区分）：
`recon/dev-reopen-proof.sh enable` → `recon/dev-entry-enabled.cjs`（入口出现 → dev 身份取数 200）→
`recon/dev-reopen-proof.sh disable` → 复跑 `W27` 自证回到关闭态。本批实测：开 5/0、关后 6/0。

### B. 授权（G-SEC-4 ~ 6）

| ID | 规格 | 为什么 | 落地形态 | 回归判据 |
| --- | --- | --- | --- | --- |
| **G-SEC-4** | 鉴权**四层**（认证 → 角色 → 边级角色门 → 对象级授权）缺一不可；**角色只能加在"边的角色集"一侧** | 把路由角色并进"调用者角色集"＝取消这道门，而真角色仍被挡（编译与阅读都看不出，L-428） | `AuthContext`（`t_user`/`t_user_role` 取角色，`viewer` 基线）+ `JwtContextFilter` + 工作流边声明 | `T4-6 边级角色门对账`（声明域 4 / 已执行 4 / 未执行 0，带注入自检非空转）；`T3-12`/`T3-13` 接口层用**真实角色**走通签署链 |
| **G-SEC-5** | 对象级授权必须落在**资源**上（项目/产品/需求…），不得只看角色 | 角色是"能不能做这类事"，不是"能不能动这个对象" | 域服务 `authorizeObject(...)`；审计留痕 | `T3-6`/`T3-12` 中以**非授权身份**断言 403、以授权身份断言 200（成对断言，避免"只有正例"） |
| **G-SEC-6** | 前端不得成为唯一防线 | 前端隐藏按钮不是授权；接口层必须独立拦 | 后端逐端点鉴权 | `T3-14 §S2`：绕过前端直接打接口，无凭据/越权身份必须 401/403 |

### C. 凭据与密钥（G-SEC-7 ~ 9）

| ID | 规格 | 为什么 | 落地形态 | 回归判据 |
| --- | --- | --- | --- | --- |
| **G-SEC-7** | **禁止任何默认口令进入运行态**（含管理台）；口令由环境变量注入并可轮换 | 默认口令＝身份源可被接管（本批实测：Keycloak 管理台 `admin/admin` 可直接取到管理 token） | `KC_BOOTSTRAP_ADMIN_USERNAME/PASSWORD` 取 `KC_ADMIN_PASSWORD`；`plm-keycloak-security-policy.py` 自举轮换；引用脚本一律读环境变量而非硬编码 | `T3-14 §S3`：默认口令登录**必须失败**（实测 400）；`--check-only` 无漂移 |
| **G-SEC-8** | 口令策略必须有**下限**（长度/不等于用户名/不等于邮箱），且**存量不被推翻** | 无下限＝可设"123456"；下限高于现有开发口令＝一次升级把所有人锁在门外 | realm `passwordPolicy = length(12) and notEmail and notUsername`（12 对齐存量） | `T3-14 §S3`（策略值逐项断言） |
| **G-SEC-9** | 密钥/口令**不得入制品、不得入库**；未配置时**拒绝服务而不是放行**（fail-closed） | "没配密钥就先放行"是给攻击者的后门 | `PMS_WEBHOOK_SECRET` 未配置 ⇒ 入站 webhook 一律拒；`application.yml` 默认空值 | `T3-14 §S2.3`：无签名 webhook → 401 |

### D. 登录安全策略（G-SEC-10 ~ 12）

| ID | 规格 | 为什么 | 落地形态 | 回归判据 |
| --- | --- | --- | --- | --- |
| **G-SEC-10** | 必须配置**口令爆破防护**：阈值 + 递增等待 + 窗口 + **临时锁（可自愈）**；`bruteForceStrategy` 选 **LINEAR 不选 MULTIPLE** | 无防护＝可无限猜；而 MULTIPLE 按来源 IP 汇总并临时封掉该 IP 的全部用户——CI/走查/开发同机同 IP 时，一次验证会演成"全环境登录被封" | realm `bruteForceProtected=true`、`failureFactor=5`、`waitIncrementSeconds=60`、`maxFailureWaitSeconds=900`、`maxDeltaTimeSeconds=43200`、`permanentLockout=false` | `T3-14 §S3b`**行为实测**（见 G-SEC-11） |
| **G-SEC-11** | 安全策略的判据必须打在**"正确凭据也被拒"**上，并回答"锁定三问" | "错口令被拒"是平凡事实，会伪装成策略生效 | 探针用户自建自清 | `T3-14 §S3b`：①连续 5 次错口令后**正确口令也被拒** ②**同 IP 另一账号不受影响**（非连坐）③清记录**立刻恢复**（临时锁可自愈）④探针残留 0 |
| **G-SEC-12** | 安全事件必须**留痕**（登录成功/失败/登出/改密 + admin 事件），保留期明确 | 事后无法取证"被爆破过"＝没有安全运营的基础 | `eventsEnabled=true` + `enabledEventTypes` 四类 + `eventsExpiration=2592000` + `adminEventsEnabled=true` | `T3-14 §S3`（事件配置逐项断言） |

| **G-SEC-16** | 有状态组件升级必须**可回滚**：先备份、后升级、再断言（issuer 未变 / 真实登录可用 / 迁移日志），回滚步骤写进脚本 | "知道怎么升不知道怎么退"＝一次升级可能永久毁掉身份源 | `recon/kc-upgrade-26.sh`：`pg_dump` keycloak 库（含 sha256）→ 重建容器 → 断言 issuer/version/登录；回滚命令随脚本输出 | 升级脚本自身即判据（本批实测：issuer 未变、迁移 25→26.6.2、`LOGIN_OK`） |

## 3. 免认证白名单（当前闭集，改它必须走 §5 纪律）

| 路径 | 为什么必须放开 | 自护方式 | 代价 |
| --- | --- | --- | --- |
| `/actuator/health` | 容器健康检查与 CI 健康探测的锚 | 只回 `{service,time,status}`，无 DB/环境/依赖明细 | 无业务数据 |
| `/error` | 不放开会让 `sendError(415/500)` 在响应已提交后再触发鉴权异常 ⇒ 客户端只见 socket hang up | 仅承载错误体 | 无 |
| `/swagger-ui.html`、`/swagger-ui/**`、`/v3/api-docs/**` | **7 个已登记 CI 套件匿名取 api-docs** 做判据↔能力对账/静默参数审计/契约对账 | 只读、无业务数据 | 接口清单与字段名对外可见（当前仅本机可达） |
| `/api/v1/_platform/pms/webhook` | PMS→PLM 入站 webhook，不能带用户身份 | **HMAC 验签**；密钥未配置即拒绝一切入站（fail-closed） | 无 |
| `/api/v1/documents/files/download-by-ticket` | 浏览器原生下载是裸导航，带不上 Bearer | 一次性票据（服务端定作用域、只存 sha256、坏票/无票 401） | 无 |

> **收口记录**：批次33 之前 `/api/auth/**` 整段豁免（匿名 `GET /api/auth/me` 返回 200）。
> 经裁定（r2）删除——它是"除登录页外都需认证"的唯一不明豁免且**全仓无匿名消费者**，收口零影响（匿名访问现为 401）。

## 5. 变更纪律（改安全相关配置的"必须"）

1. **新增豁免/旁路/默认值**：同批更新 ①白名单（含理由与代价）②`T3-14` 的目标集合 ③受影响文档（本文 §3/§4 + 05 §11）。
   只改代码不改判据 ⇒ CI 必红（这是设计意图，不是障碍）。
2. **关闭/开启认证类功能**：必须给出**双向取证**（关闭态断言 + 打开态一次实测），否则"关闭"与"删除"无法区分（G-SEC-3 配套）。
3. **升级组件**：先核可得性（用实际坐标）→ 分两段（同线/跨大版本）→ 每段全量 CI + 发布 + 更新 §S4 下限断言；有状态组件先备份。
4. **任何"临时打开"**：必须有还原步骤与自证（本批 dev 打开取证 → 立即还原 → W27 复跑自证）。
5. **安全结论**：必须写明扫描范围、时间点、工具、残余条目与**没扫到什么**；禁止把"版本达标"写成"无漏洞"。
6. **判据不得为了变绿而放宽**：诊断性信息可以加（如 `gridRefreshed`），阈值与判定口径不得改（本批 P5 加固即此例）。

## 7. 新域 / 新批次接入检查表（照抄，不许"参照现有实现"）
