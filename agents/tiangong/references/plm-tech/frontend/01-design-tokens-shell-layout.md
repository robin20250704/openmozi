### 1.2 焦点环

```
:focus { outline: 2px dashed #0ea5e9; outline-offset: 2px; border-radius: 3px; }
```

- **虚线 + 清爽蓝** `#0ea5e9`（sky-500），鼠标点击和键盘 Tab **均显示**。
- AG Grid 单元格/表头：`outline-offset: -2px`（内嵌不溢出）。
- AG Grid 选中行：`.ag-row.ag-row-selected { outline: 2px dashed #0ea5e9 !important; outline-offset: -2px !important; }`（行点击不移动 DOM focus，用选中样式替代 `:focus`）。

### 1.3 字体

```
font-family: system-ui, -apple-system, "Segoe UI", Roboto, "PingFang SC", "Microsoft YaHei", sans-serif;
```

- 等宽字体（编号/代码）：`ui-monospace, Consolas, monospace`（`.mono` 类）。
- AG Grid 字号：`12.5px`；行高 `32px`；表头高 `28px`。

## 2. 应用骨架（App Shell）

```
≥1055px（宽屏，单行顶栏）
┌──────────────────────────────────────────────────┐
│ ☰  品牌        [🔍 全局搜索 400px · 🌐全部]     ✦AI  🔔  用户 │
│                        ← 顶栏正中 →                │
├──────────────────────────────────────────────────┤
│ content (flex:1, padding:18px 22px, overflow:auto) 满宽 │
└──────────────────────────────────────────────────┘
点 ☰ ⇒ 抽屉浮层（260px + 遮罩），**内容不被推动**

≤1054px（紧凑/手机，两行顶栏）
┌──────────────────────────────────────────────────┐
│ ☰  品牌          ✦AI  🔔  用户                    │
│ [🔍 全局搜索（可缩） · 🌐全部]  ← 独占第二行整行     │
├──────────────────────────────────────────────────┤
│ content（手机再叠 `.sidebar{width:min(78vw,300px)}`） │
└──────────────────────────────────────────────────┘
```

| 区域          | 规格                                                                                                                                           |
| ----------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| **topbar**  | 两档形态，**同一个 `z-index:3000`**。**≥1055px**：`height:56px` 单行，全局搜索**绝对居中**（`left:50%` + `translateX(-50%)`，宽 `400px`）。**≤1054px**：`flex-wrap:wrap; height:auto`，搜索改回流内 `order:10; flex:1 0 100%` **独占第二行整行**，第一行只放 ☰/品牌/右簇。底色/边框（**UI 优化轮 2026-09 由深色改白**）与品牌名、AI 徽章、用户片不变 |
| **sidebar** | **浮层抽屉**（2026-10-08 用户裁定，PC 端与手机端统一）：`position:fixed; top:0; left:0; width:260px; height:100%; z-index:3100; transform:translateX(-102%); transition:transform .22s`，由 `body.nav-open` 解锁为 `transform:none`。**不占行内宽度** ⇒ content 恒为满宽。手机（≤768px）为 `width:min(78vw,300px)`。分组标签（10px/600/letter-spacing:2px）+ 导航项（13px，hover `--sidebar-hover`，active `--primary` 白字） |
| **☰ 开关**   | `button.nav-toggle`，顶栏最左。`aria-expanded` 与 `body.nav-open` 同一真身；桌面 40×40、≤1054px 44×40（`S-17` 热区）。**抽屉打开时抽屉盖住顶栏左角**，点该处落在抽屉内容上（不会误触发二次切换） |
| **遮罩**     | `.nav-mask`：`body.nav-open` 时才 `display:block`（`position:fixed; inset:0; rgba(15,23,42,.45); z-index:3050`）。三条关闭路径：点遮罩 / `Escape`（焦点还给 ☰）/ 切换路由。**不锁滚动、不做焦点陷阱** |
| **全局搜索** | 一处真身：`.topbar .td-search`（条 32px、桌面 `height`/`border-radius` 由类给）内 `[🔍] input（flex:1 1 auto，可缩） + select（flex:0 0 auto，min-width:88px）`，两者 `align-self:stretch` ⇒ **高度恒等**（用户 2026-10-08 原话「高度要永远保持一致」）。⚠ 尺寸**只写在类上**：`GlobalSearch.tsx` 里不得再出现内联 `height/width`——内联优先级高于类规则，手机段样式会被静默压掉（这正是用户截图「下拉比搜索框高一截」的成因） |
| **content** | `flex:1; padding:18px 22px; overflow:auto`。**唯一的外层滚动容器**——全屏面板复用此滚动条，不产生内部滚动。抽屉是浮层，**content 不因开合位移** |

> ⚠ 断点 **1054** 的来历（实测推导）：右侧控件簇最左缘 = 视口宽 − 319；居中 400px 的搜索盒右缘 = (W+400)/2；
> 要求两者留 ≥8px ⇒ **W ≥ 1054**。769–1053px 这段右簇约 426px（含 AI 文字），留给居中框的净空已不足 400px，
> 故并入紧凑形态而非做一个越用越窄的居中框。**判据/断言的居中基准是顶栏盒，不是 `innerWidth/2`**
> （桌面有竖滚动条，`left:50%` 居中的是排版视口，天然差 ≈7.5px）。

### 2.1 侧边栏导航分组（用户视角）与图标统一（2026-09-28 UI 走查整改）

**分组按"用户要做什么"而不是"系统分了几层"**（用户裁定：原「数据层/流程层/支撑层」是架构视角，使用者找不到自己要去的页）。
固定五组（`main.tsx` 的 `.sect` 顺序即此）：

| 组 | 收录 | 理由 |
|---|---|---|
| **日常工作** | 工作台 | 每天第一落点，单独成组 |
| **产品数据** | 需求管理 / 物料库 / BOM 管理 / 产品结构 / 产品包 / 文档中心 | "我要管的对象"——数据对象全集 |
| **项目与流程** | 项目管理 / 计划任务 / 项目驾驶舱 / 任务书工作台 / 工程变更 | "我要推进的事"——流程与执行 |
| **IPD 工作台** | 管道驾驶舱 / CBB 资产库 / 治理台 / 事件控制台 | IPD 方法论专属视图 |
| **管理与支撑** | 注册法规 / 上市后监督 / 风险台账 / 风险规则 / 系统设置 | 合规与系统管理 |

三条配套规则：

1. **WIP 功能下线导航但保留路由**：未完成页（实例：路标四象限 `/roadmap`）从侧边栏移除导航项，**路由保留**——深链/演示可用，导航里不出现"点了是半成品"的入口。恢复导航 = 导航数组加回一行。
2. **图标一套**：27 个导航项**全部用 emoji**，禁止几何字形（▦◈▤⇄§⚙ 一类）与 emoji 混用——混用后侧栏视觉权重不一致（走查抓到的正是几何字形发灰、emoji 发彩的失衡）。
3. **组的增删是用户裁定事项**：新增模块时先归组，归不进去才新建组，并在本节登记。
4. **导航的「可见性」是壳层形态，不是导航项的属性**（2026-10-08）：27 项一项没少，但 PC 与手机统一收敛为 ☰ 抽屉。
   改导航项时只改 `NAV` 数组；**不要**再往桌面样式里加"让侧栏常显"的规则——那是两处真身。
   门禁：`plm-shell-layout.cjs`（`plm-suites.tsv` 的 `W101`）守 ☰/抽屉/遮罩/搜索条两档形态 + 三条关闭路径。

## 3. 页面布局模式

### 3.1 标准业务页面结构（从上到下）

```
breadcrumb（12px, --text-faint）
page-head（h1 20px/700 + 操作按钮行）
ctx-bar（浅色上下文条 #f8fafc，12.5px）
toolbar（筛选控件行，13px）
tri（三栏布局：树 | 网格 | 详情面板）
```

### 3.2 各区域规格

| 区域             | class         | 规格                                                                                                                             |
| -------------- | ------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| **breadcrumb** | `.breadcrumb` | `font-size:12px; color:--text-faint; margin-bottom:10px`。链接用 `--primary`                                                       |
| **page-head**  | `.page-head`  | `display:flex; justify-content:space-between`。h1: 20px/700。按钮：`.btn`（7px 14px, 6px 圆角, 1px 边框），`.btn.primary`（`--primary` 底白字） |
| **ctx-bar**    | `.ctx-bar`    | `background:#f8fafc; color:--text; border:1px solid --border; border-radius:8px; padding:10px 16px; font-size:12.5px`（**UI 优化轮 2026-09 由深色改浅色**：深色只保留给侧边栏，消除模块间深色/浅色跳跃）。含项目选择器 + **门进度**（`阶段门进度 x/N`：x = 已决策**评审门**数、N = 门点总数；2026-09-22 前为「阶段门进度 x/7」，读的是已作废阶段门计数，恒 0） |
| **toolbar**    | `.toolbar`    | `display:flex; gap:10px; flex-wrap:wrap`。控件：`padding:6px 10px; border:1px solid --border; border-radius:6px; font-size:13px`   |

### 3.3 三栏布局

```css
.tri { display: grid; grid-template-columns: auto minmax(0, 1.5fr) minmax(330px, 1fr); gap: 16px; align-items: start; }
```

- **第一列 `auto`**：分类树抽屉（收起 36px 窄条 / 展开 **196px** 面板——280px 减 30%；分类行**不显示统计数字**，后端 `/requirement-classes` 相应去掉 per-class `count(*)` 子查询降低查询消耗）。
- **第二列 `minmax(0, 1.5fr)`**：数据网格 + RTM 覆盖率条——占剩余空间约 **60%**（两次收窄让位详情面板）；默认列宽：标题 **230px**（15 个汉字）、类型 **75px**（5 英文字符）、状态 **105px**（9 英文字符）、优先级 **120px**（11 英文字符）。
- **第三列 `minmax(330px, 1fr)`**：详情面板——吃剩余约 40% 空间。
- 响应式：`@media (max-width:1200px) { .tri { grid-template-columns: 1fr; } }`

#### 3.3.1 无分类树时的两栏变体（左右并列 `.dual.split` 族）

> 追加于 2026-09（任务书工作台重构）。本小节**只追加**，不改动 §3.3 三栏（`.tri`）与 `.dual.split` 既有 40%/60% 的规定（项目管理页仍按 40% 表格 / 60% 详情）。

- 页面无分类树抽屉时，主区用两栏网格 `.dual.split`（`grid-template-columns: 40% minmax(0,1fr)`）：左表格 40% / 右详情面板 60%（基准实例：项目管理页）。
- **等分变体 `.dual.split.even`**（`grid-template-columns: minmax(0,1fr) minmax(0,1fr)`，左 50% / 右 50%）：当业务对象详情内容量大、表格列多，40% 宽度放不下关键列时使用。**当前用途 = 任务书工作台（`/charter`）**：左任务书 AG Grid 表格 50% / 右任务书详情面板（DetailPanel + 流程时间线 + 财务/CDT 页签 + 评审工作台）50%。
- **结构类页面（左栏是树 / 列表，右栏是详情）一律用 `.dual.split.even` = 1:1**（2026-09-27 批次54 补，用户原话"结构树、产品详情面板，宽度各50%"）。**本轮实例 = 产品结构页 `/structure`**（左结构树 / 右产品详情，含成本对比卡）。
  - **为什么不用裸 `.dual`**：`.dual` 是"左自适应 + 右**固定 360px**"，与"各 50%"相反，且它被 6 个页面共用（改默认会连带改动超出范围的页面，§3.3.1 下文 `.detail40` 的由来同一条理由）。
  - **为什么结构类页面反而需要 1:1**：它的左栏是**树**——树的每一层缩进都吃掉宽度，40% 之下三层就能把料号挤成省略号；而右栏的产品详情本身不长。两侧需求接近时才用等分。
  - 全屏互斥类照常叠加：`.dual.split.even` 与 `.dp-fullscreen-detail` 同用时，后者的 `grid-template-columns: 1fr !important` 覆盖等分（全屏只剩详情面板这一件事不受影响）。
- 使用方式：`className="dual split even"`；全屏互斥类照常叠加（`dual split even dp-fullscreen-detail` / `... grid-fullscreen-detail`）。
- 响应式同族：`@media (max-width:1200px) { .dual.split.even { grid-template-columns: 1fr; } }`（窄屏退化为单列纵向）。

**详情面板 40% 变体 `.dual.split.detail40`**（追加于 2026-09-14，S25）：

- `grid-template-columns: minmax(0, 1.5fr) minmax(330px, 1fr)`：左表格 60% / 右详情面板 **40%**，比例取自 §3.3 三栏的同一对取值（"详情面板吃剩余约 40%"）。使用方式：`className="dual split detail40"`（全屏互斥类照常叠加）。
- **为什么新增变体，而不是改 `.dual` 默认**：`.dual` 现状是 `1fr 360px`（详情约 19%），但被 **6 个页面**共用（文档/物料/变更/产品包/注册/产品结构）——改默认会连带改动超出需求范围的页面；`.dual.split` 的 `40% minmax(0,1fr)` 是"表格 40% / 详情 60%"（项目管理页基准），方向与本需求相反，也不能改。
- 当前用途：**文档中心 `/documents`、物料库 `/items`**。
- 响应式：`@media (max-width:1200px) { .dual.split.detail40 { grid-template-columns: 1fr; } }`。

**变体使用实例登记（2026-09-20 · 批次41 · 风险台账与用户管理两页接入 `.dual.split` 族；2026-09-27 批次54 增补产品结构页）**：

| 页面 | 布局类 | 比例（表格 / 详情） | 说明 |
|---|---|---|---|
| 风险台账 `/risks` | `.dual.split` | 40% / 60% | 左侧 AG Grid 风险条目列表（只读网格，§4.7.6），右侧统一详情面板（字段多、S×P 预览 + 控制措施 + 状态推进 + PMS 校准 + 处理记录，60% 才放得下） |
| 系统设置·用户管理 `/settings`（用户管理页签） | `.dual.split.detail40` | 60% / 40% | 用户明确要求"用户详情面板默认宽度占到 40%"；用户字段少（登录名/姓名/邮箱/状态/角色/身份齐备/最近更新），40% 足够且给列表让出 60% |
| **产品结构 `/structure`** | **`.dual.split.even`** | **50% / 50%** | **批次54（2026-09-27）**：用户原话"结构树、产品详情面板，宽度各50%"。左栏是**树**（层级与长料号要宽度），右栏是产品详情 + 成本对比卡——用既有的 `.even` 变体（不新造 CSS 类），不用裸 `.dual`（右栏固定 360px，与"各 50%"相反） |

两页全屏互斥类（`dp-fullscreen-detail` / `grid-fullscreen-detail`）均照常叠加。

### 3.5 全屏模式

- **详情面板全屏**：`.dp-fullscreen-detail` 隐藏非详情列，单列铺满，复用 `.content` 外层滚动。
- **网格全屏**：`.grid-fullscreen-detail` 隐藏非网格列，网格高度 `calc(100vh - 160px)`。
- 两者互斥（mutex 状态）。
- **"详情列 / 网格列"的判定口径（2026-09-28 修订）**：见 §3.6 G-UI-7-9——契约选择器同时接受"标记类挂自身"
  （`:is(.dp)` / `:is(.grid-wrap,.tree-max,.list-max)`）与"标记类挂后代"（`:has(...)`）两种挂法；
  选择器全文以 `styles.css` 为准，本节不复述。

### 3.6 对象可达性与面板默认最大化（G-UI-7，2026-09-23 立规）

> **由来（用户原话）**：「点击 物料模块的 AI查重 结果中的 相似物料条目，要弹出新的 网页TAB页来显示相关业务对象详情，**避免冲掉了当前正在处理的对象**」
> 「按照 ID 打开对象时（如物料的链接：`http://localhost:5174/items?open=526`），相关页面的对象详情面板应该**默认最大化**，避免非目标焦点的对象的 数据表格面板占用太多空间」
> 「进入各个业务对象的管理模块时（如物料管理、需求管理），**默认表格面板最大化**；当输入焦点框转移到在 对象详情面板的控件上时，对象详情面板默认最大化」
> 「这样两条要成为**整个产品**的 UI 设计规格，类似场景的实现，都有类似的操作体验」。
> 本节是**按场景判定**的规则，不是按页面的规定——任何新域接入时照此判定，不得各写一套。

#### G-UI-7-1 按 ID 打开对象：落点必须给出该对象，且详情面板默认最大化

- 入口形态（任一）：`?open=<id>`、路径参数（`/items/:id`、`/requirements/:reqId`、`/bom/:rootItemId`…）、
  新标签页深链、全局搜索跳转、工作台待办行跳转。
- 判据：容器带 **`data-panel-state="dp"`**（= `dp-fullscreen-detail`），且详情面板内容 = 该 id 对应的对象；
  目标不在当前页时按 id 直取（口径见 §5.3「深链定位优先」）。
- 禁止：落在"表格全屏"让用户自己去找那个对象；落在列表首条；落在并列态让表格占掉一屏。
- **为什么这条与 §3.6-3「进模块默认表格全屏」不矛盾**：两条都是"用户指定的默认态"，由 URL 决定谁生效——
  带 `open` 参数 = 用户已经指名了目标对象；不带 = 用户没有目标，界面不该替他占版面。

#### G-UI-7-2 打开"另一个"对象：必须新标签页，不得挤掉当前处理对象

- 适用场景：用户**当前正在处理对象 A**，界面在 A 的上下文里展示 B 的引用/候选——
  AI 查重候选、RTM 追溯目标、证据/交付件引用、基线偏离成员、关系链、评审清单里的关联对象…
- 判据：该引用必须是**真链接**（`<a href>`，不是 `onClick` 伪装的按钮）且 `target="_blank"` + `rel="noopener noreferrer"`；
  点开后**当前页 URL、选中对象、未保存草稿一字不变**（这是本规则的全部意义）。
- 不支持的类型（无落地页/无深链）：**显式不可点** + 可执行去向提示（"请到 XX 页搜索该编号"），
  绝不得拼出一个必然打不开或落到错误对象上的链接（"比不跳更坏"，见 §9 陷阱 #33 同族）。
- 反例：同页相邻对象的"上一条/下一条"**不属本规则**——那是"换个对象继续处理"，应留在当前页（§5.3）。

#### G-UI-7-3 布局三态与"默认最大化"的判定表

三个状态**互斥**（既有 CSS 契约 §3.5）。任何"表格 + 详情面板"的页面都按下表定初始态与转移：

| 进入方式 | 初始/结果状态 | 依据 |
| --- | --- | --- |
| 菜单进入模块（无 `?open=`、无路径参数） | **表格全屏**（`data-panel-state="grid"`） | 没有目标对象 ⇒ 详情面板不得占版面 |
| 按 ID 到达（`?open=` / 路径参数） | **详情最大化**（`data-panel-state="dp"`） | 有目标对象 ⇒ 表格让位（G-UI-7-1） |
| 用户点某行的单元格 | 状态**不变**（仍表格全屏） | 选行 ≠ 声明"我要看详情"；要看详情点头部 `⤢` 或聚焦其控件 |
| 焦点进入详情面板控件 | **详情最大化** | G-UI-7-4 |
| 用户点面板头部 `⤢`（按钮文案/位置不变） | 表格全屏 ↔ 详情最大化 互切 | 既有按钮语义扩展（原为"详情 → 并列"） |
| 点网格头部 `⤢` | 表格全屏 ↔ 并列 互切 | 既有行为。**注意该按钮在详情最大化态点不到**：此时整个网格卡片被 `display:none`，按钮几何 `0×0`。要从详情最大化出来用面板头部 `⤢` 或 `Esc`——这三条合起来才是一个闭合的状态机 |
| `Esc`（详情最大化时） | → 并列 | 既有 `DetailPanel` 行为，不改 |

> **已登记的例外（2026-09，UI 优化轮接入）**：产品结构 `/structure` 的"菜单进入（无深链）"初始态 = **并列 `split`**，
> 不是表格全屏——该页有用户裁定「结构树、产品详情面板，宽度各 50%」（`.dual.split.even`，2026-09-27），
> 且界面门禁 W44/plm-b54 的 B2 判据建立在"并列两栏可见"上。深链 `?open=` 仍按本表进 `dp`。
> 实现：`usePanelMax(panelClass('dual split even'), openId != null ? 'dp' : 'split')`。
> ⚠ 该页当前**不可达 `grid` 态**（无网格 `⤢` 按钮；初始非 grid、键盘/焦点路径只进 `dp`）——
> 此例外**与 `.tree-max` 是否落地无关**（`.tree-max` 已随 2026-09-28 结案落地，见下文接入现状更新）：
> 不可达的原因是左栏没有网格锚点，`grid` 态会把两栏一起隐藏（陷阱 #39 同源）。将来若要开放 grid 态，须先给左栏补独立的 grid 态契约。

#### G-UI-7-4 "焦点进入详情面板控件 → 详情最大化"的精确判据

- 触发事件：`focusin`（冒泡）落在**详情面板包裹节点内**，且当前状态 = 表格全屏。
- 只对**控件**生效：`input` / `select` / `textarea` / `[contenteditable]` / `[tabindex]`；
  点面板里的**纯文本/横幅/只读值**不触发——"我只是读到这段"不该改变布局。
- **为何无打断风险**：表格全屏态下详情面板不可见 ⇒ "聚焦其控件"只可能发生在用户已主动展开详情之后。
  展开入口 = 面板头部 `⤢`（`aria-label="全屏编辑"`，既有锚点 `dp-submit` 一族不动）。
- 退出：`⤢` 或 `Esc`（→ 并列）；再次进入表格全屏走网格头部 `⤢`。

#### G-UI-7-5 可判定锚点（规格自带，走查直接可用）

| 锚点 | 位置 | 用途 |
| --- | --- | --- |
| `[data-panel-state]` = `grid` \| `dp` \| `split` | 页面主容器（同时承载 §3.5 三个类之一） | 一眼读出布局态，不必解析 class 字符串 |
| `[data-objref]` + `data-objref-type` / `data-objref-id` | 新标签页对象链接 | 断言"是真链接 + 指向哪个对象" |
| `[data-objref-text]` | 不支持类型时的纯文本形态 | 反向断言"不可点且给了去向" |

#### G-UI-7-6 唯一实现点（防第 13 份副本）

布局三态的状态机由 **`hooks/usePanelMax.ts`** 一处实现（`state` / `showGrid` / `showDetail` / `showSplit` /
`containerClass` / `onExpandChange` / `toggleGrid` / `onFocusCapture`，入参 `initial` 由页面按 URL 判定）；
**三态类名的拼接也只有一处**：页面声明"我这页并列时长什么样"（`const PANEL_CLASS_X = panelClass('dual split detail40')`），
容器写 `className={panelMax.containerClass}`，**不得**再写成 `` className={`dual split detail40 ${panelMax.containerClass}`} ``
（那会让 base 类名同时由页面和 hook 各拼一次；实测渲染出 `dual split detail40 dual split detail40 grid-fullscreen-detail`：
CSS 后果为零，但 ① `className` 不再是可信读数 ② "哪三个类构成三态"又变成两份）。
新标签页对象链接由 **`components/ObjLink.tsx`** 一处实现（落地 URL 走 `lib/routes.ts` 的 `deepLink()` 单一事实源，
类型标签走 `lib/objRef.ts` 的既有标签表）。
**页面里不得再出现第二个 `dpFull`/`gridFull` 手写状态对**，也不得再手拼 `?open=` 深链。
每个接入页须带稳定网格锚点 `data-testid="<域缩写>-grid"`（走查与回归门据它点名，见 `plm-suites.tsv` W42/W43）。

#### G-UI-7-7 「回车看详情」：表格里选中对象后按 `Enter` → 详情最大化并把焦点送进面板

**规格**：页面主容器上挂 `onKeyDownCapture`；三条触发条件**全部满足**才动作——
① `Enter`（无 `Alt`/`Ctrl`/`Meta` 修饰）；② 事件目标在数据单元格内（`.ag-cell`）且**不在**编辑态
（`.ag-cell-inline-editing` / `.ag-cell-editor` / `.ag-rich-select`）；③ 网格里**确有选中行**（`.ag-row-selected`）。
动作 = 状态切到 `dp`（详情最大化）+ 把键盘焦点送进详情面板第一个可编辑控件
（面板内没有可编辑控件时退化为头部按钮/面板自身）。任一条件不满足即**完全放手**，
不干扰既有键盘语义（Enter 进入编辑 / 光标下移）。

**为什么必须在捕获阶段**：AG Grid 自己的键盘监听挂在网格根节点上；捕获阶段先于它执行，
这里的 `preventDefault()` + `stopPropagation()` 才能真正拦下网格的 Enter 默认行为——
否则"看详情"会顺带改数据或把焦点跑掉。

**为什么焦点要延到渲染提交之后**：回车那一刻面板正由 `grid → dp` 重渲染，面板内部节点可能被卸载重建，
此刻 `focus()` 会**静默失败**（实测：走查里 7 个页面全部读到 `document.activeElement === <body>`，
而同一时刻由外部脚本 `focus()` 同一控件却成功）⇒ 焦点请求走 `useState` 计数 + `useEffect`（渲染提交后执行）。

实现：`hooks/usePanelMax.ts` 的 `onGridKeyDown` + 焦点 effect（G-UI-7-6 的唯一实现点）；
判据：`W42-批次52对象可达性与默认最大化UI` 第 7 段（7 个已接入页面逐页点名）。

> **规格缺口留痕（批次53 发现并补写）**：本节此前**只存在于代码注释与走查里**——
> `usePanelMax.ts`、`DetailPanel.tsx` 都写着"G-UI-7-7"，而 §3.6 只定义到 G-UI-7-6，
> 于是出现"代码引用了一条规格里查不到的规则号"。判据不是"注释写了就算"：规格必须能被独立检索到。

#### G-UI-7-8 展开态（详情最大化）的布局契约：附加区块**独占整行**（2026-09-23 批次53）

**规格**：详情面板**展开态**下字段区是两列网格（`.dp.expanded .dp-body`），而 `extra` 槽位
（流程条 / 订正取代 / RTM 追溯 / 流转动作 / 处理记录）承载的都是**整宽区块**，
必须 `grid-column: 1 / -1`——实现是 `DetailPanel` 把 `extra` 包进 `.dp-extra` + `styles.css` 里的一条规则；
**不得**作为普通网格项被自动排进某一行剩下的那一格。

**为什么**（批次53 真浏览器几何实测，需求详情面板）：不修时 `extra` 落在最后一行的**右半栏**
（w=692 / 整行 1353 = **51%**），把同行的「法规条款引用」撑到 **418px**（而它自身内容只有 30px）——
左侧输入框孤零零居中（用户原话"很空"）；右侧四类控件在 51% 宽度里一路换行（用户原话"纵向空间很长"）。
修后：附加区块 w=1353（**100%**，左缘与字段区对齐）、同行字段行高回落到 **30px**、四类控件各占满整行。

**纪律**：判据落在**唯一出口**（`DetailPanel` + `styles.css`），14 个详情面板同时受益；
页面**不得**自己给 `extra` 写内联 `gridColumn`（批次53 已把 CBB 资产库页此前那处内联同义写法上收删除，
同 `.dp-row.wide` 的处置口径，见 doc 14 的 G-UI-2b / G-UI-2c）。

**判据（可复跑的机器断言）**：`W44-批次53详情面板附加区块独立整行UI`——附加区块宽 ≥ 0.9× 字段区整行宽、
与**任何**字段行纵向不相交、整体位于最后一个字段行之下、区块内四类控件各自独立占一行且各占满整行宽、
字段行行高 ≤ 1.6× 自身最高子元素；**反例断言**：字段区仍是两列（不得把面板退化成单列）。

#### G-UI-7-9 左栏最大化契约扩展与"非 AG Grid 左栏"接入（2026-09-28 批次 T18/风险规则整改）

**背景**：§3.5 的全屏契约原先只认 `.grid-wrap`（AG Grid 容器）——左栏是**树**或**纯 HTML 表格**的页面
（C 档）接不进来。本节把契约标记类扩展为三个，并结案 C 档。

| 标记类 | 语义 | 首接页面 |
|---|---|---|
| `.grid-wrap`（既有） | AG Grid 容器 | 全部网格页 |
| `.tree-max` | 左栏最大化的**树/结构面板**（类名刻意不叫 `.tree-panel`——那是需求页抽屉树的 196px 窄条既有类，复用会撞宽） | 产品结构 `/structure`（左结构树，头部加 ⤢ 三态切换） |
| `.list-max` | 左栏最大化的**纯表格列表**（无 ag-grid 包裹的 `<table>` 清单） | 风险规则 `/risk-rules` |

**"详情列"侧**：右栏直接挂 `.dp` 类（既有 DetailPanel 类）即被 `dp-fullscreen-detail` 认作详情列——
用于不使用 `DetailPanel` 组件的自绘表单（风险规则页的编辑表单是基准实例）。

**选择器必须同时覆盖"挂自身"与"挂后代"两种挂法**（`:has()` 只查后代；三个标记类都存在直接挂在
容器子节点自身的页面）：

```css
.dp-fullscreen-detail > :not(.dp):not(:has(.dp)) { display:none !important; }
.dp-fullscreen-detail > :is(.dp), .dp-fullscreen-detail > :has(.dp) { grid-column: 1 / -1; }
.grid-fullscreen-detail > :not(.grid-wrap):not(.tree-max):not(.list-max):not(:has(.grid-wrap)):not(:has(.tree-max)):not(:has(.list-max)) { display:none !important; }
/* grid-column 规则同理并列 :is(.grid-wrap,.tree-max,.list-max) 与 :has(...) 两个分支 */
```

> ⚠ 真事故（2026-09-28）：第一版扩展只写了 `:has(.tree-max)`，而标记类挂在卡片自身 ⇒ 全屏态下
> 左右两列**同时被隐藏、整页空白**。走查截图抓到后补 `:is()` 分支，并对结构页 grid 态（树宽=容器宽）
