## 2. PoC 策略（风险前移）

> 选型判据要求：高风险候选**采纳前必须最小质量可行性验证**。PoC 在 P0 阶段并行执行，不通过即降级/换型。

### 2.1 PoC 时间线

```
W1~W4（P0 前半段并行）：
  PoC-1  PG JSONB 性能          → 不通过则加 ES 前置
  PoC-2  PG 递归 CTE            → 不通过则上 Apache AGE
  PoC-3  AG Grid SSRM           → 不通过则换 glide-data-grid
  PoC-4  AG Grid Tree 懒加载    → 不通过则缩 BOM 展示深度
  PoC-10 Kafka Outbox           → 不通过则换 RocketMQ

W5~W8（P0 后半段并行）：
  PoC-5  Univer 公式引擎        → 不通过则用 Excel 模板下载
  PoC-6  Excel 粘贴管道         → 不通过则降级为 CSV 导入
  PoC-7  元数据驱动列生成       → 不通过则硬编码列（技术债）

W17~W20（P4 前半段并行）：
  PoC-8  DeepSeek Agent         → 不通过则降级为规则模板
  PoC-9  RAG 强制引用           → 不通过则禁用 AI 回答（仅 AI 建议）
```

### 2.2 PoC 验收标准

| PoC | 通过标准 | 不通过降级方案 |
|---|---|---|
| PoC-1 | 100 万行 JSONB GIN 查询 P95 < **500ms**（验收线；**性能目标 100ms**，见文末口径说明） | ES 前置（增加运维复杂度） |
| PoC-2 | 10 层 BOM 10 万节点 P95 < 3s | Apache AGE 图扩展 |
| PoC-3 | 百万行 SSRM 滚动 60fps | glide-data-grid（放弃 AG Grid 树形） |
| PoC-4 | 5 万行树展开 < 200ms/层 | 限制 BOM 展示深度 ≤ 5 层 |
| PoC-5 | 500 行×20 列公式重算 < 500ms | Excel 模板下载/上传（牺牲实时性） |
| PoC-6 | 500 行粘贴端到端 < 10s | CSV 文件导入（牺牲交互性） |
| PoC-7 | 加属性零发布生效 | 硬编码列定义（技术债，后续重构） |
| PoC-8 | 变更分析初稿 P95 < 8s，引用 100% | 规则模板生成初稿（无 AI 理解能力） |
| PoC-9 | 无引用不回答，拒答率 100% | 禁用 AI 自由回答，仅保留 AI 建议 |
| PoC-10 | 并发写入零丢失 | RocketMQ（增加维护成本） |

> **PoC-1 两个数值的口径（2026-09-17 裁定，消除本文与 `01-技术选型决策.md:276`、`05-技术架构设计.md:218` 的矛盾）**：
> **验收线 = P95 < 500ms**（与网格列表查询 SLO 同一条线，是"过不过"的判据）；
> **性能目标 = P95 < 100ms**（更严，是优化方向，不达不判失败）。原先此处写 100ms、另两处写 500ms，
> 属于同一指标两个阈值并存——**保留更严的一方作为目标、以更宽的一方作为验收线**是本项目的既定口径
> （见 `16-性能保障规格.md` §2 与该文 §6 C-1）。

## 3. 执行方式

> 本项目全部由 **Agent 开发**执行，不设人工角色与人力估算。工作包拆解与工期（`plm-tech/05`）仅用于计划排期与里程碑管理。

**执行与协作机制**：
- 每个工作包由交付型 Agent 实例按 `plm-tech/05` 的依赖顺序执行，产出物（代码/文档/验证报告）落库为可审计交付件；
- **API 契约**：OpenAPI 自动生成，前后端契约校验；
- **代码审查**：PR 至少一次独立审查；领域服务与合规相关变更须架构级复核；
- **PoC 评审**：每个 PoC 完成后按通过标准评审，不通过即执行降级方案。

## 6. UI 原型驱动的实施优化

> 基于 `docs/plm-ui-prototypes/` 的 8 模块 + 6 旅程 + 设计系统，对实施方案的优化。

### 6.1 前端开发效率提升

| 优化项 | 原方案 | UI 原型驱动优化 | 效果 |
|---|---|---|---|
| UI 组件库 | Ant Design（通用） | shadcn/ui + Tailwind（原型推荐） | 组件源码可控；设计系统色板直接映射 |
| 表头逻辑 | AG Grid 内置 | TanStack Table v8 headless 驱动 | 列定义/排序/过滤逻辑层与渲染解耦 |
| 布局 | 自研 | 三栏布局规格化（220+320+flex+280px） | 布局一次开发，8 模块复用 |
| 色板 | 通用 | AI 紫 #8b5cf6 / 医疗青 #0d9488 明确 | 设计系统一致，减少返工 |
| 模块开发 | 按域分 | 按 UI 原型 8 模块分（WP-13~17） | 前端工作包与原型一一对应 |

### 6.2 旅程驱动的验收优化

| 优化项 | 原方案 | UI 原型驱动优化 | 效果 |
|---|---|---|---|
| 验收路径 | 按 WP 逐个验收 | 按 J1~J6 旅程端到端验收 | 验收更贴近真实用户路径 |
| 里程碑 | 按 P0~P5 分期 | M4 按 8 模块 UI 可交互验收 | 前端验收标准更具体 |
| BR 校验 | 后端单元测试 | UI 界面 BR 标注→E2E 测试 | BR 校验可视化可走查 |

### 6.3 项目上下文条（跨模块设计模式）

UI 原型 07-project-management 定义的项目上下文条适用于所有模块：
```
📂 当前项目: 📎PLM:PROJ:R3 · 呼吸机R3 · II类 · G3设计输出▓▓▓▓▓▓▓▓░░92% · OP同步:✅ · [切换项目▼]
```

**实施**：作为 WP-13（前端基座）的公共组件一次开发，8 模块复用——减少重复开发，保证一致性。

### 6.4 深链导航系统（跨模块基础设施）

UI 原型定义的 `📎 PLM:TYPE:CODE#REV` 深链导航是所有模块的公共依赖。

**实施**：作为 WP-05（Resolver）+ WP-13（前端基座）的公共基础设施，在 P0/P1 阶段优先完成——后续所有模块和 AI Agent 都依赖此能力。
