# 健康指标与能量预算（health）· PLM 客服

> 读取时机：每轮开工（`plm-kb.cjs doctor` 给出文件与缓存状态）、每次交付后追加、L2/L3 整理时汇总。
> 口径：指标是**偏置的可操作化**，但"当指标成为目标，它就不再是好指标"——大 cycle 必须自审"这些指标是否仍服务于 mission"（防 Goodhart）。

## 一、健康指标（当前基线：2026-09-27 首轮）

| 指标 | 定义 | 数据来源 | 当前值 | 警戒线 |
| --- | --- | --- | --- | --- |
| 一次命中率 | 未被追问的答复 / 总答复 | `plm-answer-quality.md` | 无数据（尚未受理真实用户） | < 70% |
| KB 命中率 | 命中 KB 的答复 / 总答复 | 同上 | 无数据 | < 50% |
| 推测率 | 依据=推测的答复 / 总答复 | 同上 | 无数据 | > 30% |
| 需求被采纳率 | 推进到 `ANALYZED` 及以后 / 登记总数 | `plm-requirement-outcome-tracker.md` | 0 / 1（REQ-2026-3230 仍 PROPOSED，正常） | < 50% |
| 重复登记率 | 强行 `--allow-duplicate` 登记的 / 登记总数 | 台账 notes 含 `[replay]` 或人工记录 | 0 | > 0（任何一次都要复盘） |
| 查重命中率 | 查重命中并**改判为合并**的次数 / 查重总次数 | 台账 + VOC | 无数据 | ——（命中后合并是**好**信号） |
| 台账-运行态漂移率 | `track` 报告不一致条数 / 台账条数 | `track` | 0 | > 0（立即回写） |
| 工具可用率 | `check` 通过步骤数 / 7 | `check` | 7/7 | < 7（不许带病登记） |
| 登录预算 | 完整 SSO 登录次数 / 总登记次数 | 工具日志（`source=cache/refresh/sso`） | 1 次 SSO / 1 次登记（首轮） | > 1 次 SSO 每 10 次操作 ⇒ 检查 token 缓存 |

## 二、能量预算（token / 时间 / 注意力）

| 预算 | 约束 | 分配策略 |
| --- | --- | --- |
| **检索预算** | 每轮 ≈ 每次答复 ≤ 2 次大文件读取 | 先 `plm-kb.cjs boot/query`（一次调用替代多次读）；KB 未命中才翻只读源码 |
| **登录预算** | 完整 SSO 登录是**最贵**的动作（起浏览器 + 走授权码流，约 25s） | 三级：缓存 token > refresh 续期 > 完整登录；不要 `--force` 除非排障 |
| **下游注意力预算（最稀缺）** | 登记条数 = 消耗分析人 + 开发人的注意力 | 查重门 + 洞察线聚类（同一痛点最多一条需求）；**不登记"已答复即可解决"的问题** |
| **答复时效预算** | 用户等着用系统 | 已核实的立即答；未核实的**当轮**给"未核实 + 验证路径"，不拖到查清再答（V-07） |
| **整理预算（L2）** | 低频 | KB 任一文件 > 400 行 / 索引命中率下降 ⇒ 触发整理 |

## 三、降级阶梯（故障时按序执行，不跳级）

1. **登录失败** → 读错误里的"是否已提交登录表单"判据 → 跑 `plm-req.cjs doctor`（清孤儿浏览器）→ 换专用端口 → `PLM_HEADLESS=0` 有头模式看登录过程 → 报告并请人确认 `.env` 与账号状态。
2. **证书错误** → 确认用的是本工具自起实例（不是复用别人的）→ 确认带了 `--ignore-certificate-errors`。
3. **登记被拒（400/403）** → 按 `plm-requirement-registration.md` 的失败处置表逐项匹配；**不要盲目改字段重试**（会掩盖真因）。
4. **KB 检索不到** → 明确答复"未核实 + 验证方法"（C-07）→ 把该缺口记入 `plm-answer-quality.md` 的 KB 缺口列 → L2 时补条目。
5. **token 反复过期** → 检查缓存文件是否被删/身份是否变更 → 确认 `PLM_TOKEN_SKEW`（默认 120s 提前量）。

## 四、自修复回路（免疫系统类比）

- **识别异常**：`check` 失败、`track` 出现漂移、答复被连续追问同一问题、同一痛点被登记两次。
- **降级/隔离**：停止登记动作、把"当前不确定"写进答复而不是猜。
- **修复**：修 `.env`/端口/浏览器；补 KB 条目；把教训写入 `plm-lessons.md`（即时写）。
- **上报**：涉及账号、权限、环境变更的修复一律**升级到人**（C-12）——客服不自行改系统。
