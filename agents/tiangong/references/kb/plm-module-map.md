### 2.3 运行态门点字典（**11 个门点，权威 = `t_gate_map`**）

```
DCP0 / TR1 / TR2 / DCP1 / TR3 / DCP2 / TR4 / DCP_ES / TR5 / TR6 / DCP3
```
- 门点总数 **11**，由后端下发、**前端不得写死**（`ProjectDtos.java:167`、`:232-233`；`ProjectService.java:876`、`:836`）。
- 界面口径：项目详情面板「项目统计 · **DCP0-DCP3**」+「阶段门 **x/11** 通过」，`x` = 该项目**已决策的评审门数**（结论 ∈ `GO`/`GO_WITH_RISK`/`PASS`/`COND`）；与驾驶舱的 `已决策 n/总数`、时间线的「评审门 x/11 已决策」**是同一个数**（附录C:27-30、03:84-87、16:107-108）。
- **门只有两类**：**DCP** = 商业决策（IPMT 判定，**驱动阶段流转**，时间线画**菱形**，结论 `GO`/`GO_WITH_RISK`/`REDIRECT`/`TERMINATE`）；**TR** = 技术评审（PDT/SE 判定，**不流转阶段**，画**圆角方形**，结论 `PASS`/`COND`/`FAIL`）（03:93-96、03:150-156）。
- **旧门码 → 新门码映射**（读历史材料用；`t_gate_map.old_gate_code`）：`G1→DCP1`（计划决策）、`G2→DCP2`（开发决策）、`G3→TR3`（详细设计评审）、`G4→TR5`（设计确认评审）、`G5→TR6`（设计冻结/转换）、`G7→DCP3`（发布决策）。**G1–G7 阶段门与"四方签署"已作废**（附录C:23-35、附录A Q5，附录A:58；`MilestoneController.java:124`、`PrecheckService.java:1342`、14:202）。
- **门线唯一判据**：`GET /api/v1/reviews/precheck?projectId=<id>&gateCode=<门码>` —— **只有 `severity=BLOCKING` 的失败项才阻断**；`ADVISORY` 只报出（附录C:65-70、17:231-233、16:104）。

> ⚠ **口径落差（客服须知）**：`ipd\README.md` 的 5 个 KCP 写作 `CDCP/PDCP/ADCP/LDCP/GA`（IPD 标准方法口径），而**运行态门点是 `DCP0/DCP1/DCP2/DCP3/DCP_ES`**（`t_gate_map` 口径）。**两套 KCP 与 DCP 编号的逐项对应关系，在已读文档中未见明文 ⇒「未核实」**。给用户指路时**一律用运行态门码（DCP0…/TR1…）**，因为界面上显示的就是它们。
> 同理：`ipd\README.md` 的 **6 阶段**（概念/计划/开发/验证/发布/生命周期）与 PLM **项目生命周期 10 状态**（立项/概念/计划/开发/验证/注册申报/设计转换/上市/维护/退市，03:70-72、附录B §4）**不是同一套枚举**，逐项映射**未核实**。
