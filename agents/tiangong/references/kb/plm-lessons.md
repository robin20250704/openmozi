# 错误教训（lessons）· PLM 客服

> 写入时机：**即时写**——每次分诊失误、依据说错、登记被打回、模板缺陷被发现后立即登记（不要攒着）。
> 条目纪律：症状 / 成因 / 修复 / 证据 四段；不贴大段代码或长文。

---

## L-001 PLM 的"来源"有两套词表，混用必被 400 打回

- **症状**：`submit` 提交时服务端返回 `400 ATTR_INVALID`：`REQ.sourceType 非法值: CUSTOMER（合法值: [MARKET/STANDARD/RISK/CAPA/CLINICAL/OTHER/PLM_SELF/REGULATION]）`。
- **成因**：`sourceType`（需求来源）与 `sourceChannel`（来源通道）是**两个字段、两套词表**。工具最初把 `sourceChannel` 的五值（`MARKET/CUSTOMER/REGULATION/COMPETITOR/INTERNAL`）抄来当 `sourceType` 用——**语义看起来一样，值域完全不同**。
- **修复**：以服务端为准写死两套词表，并在 `check` 里加"词表一致性"自检（读 `/_platform/metadata/detail-fields?objType=REQ` 比对），漂移即报红。
- **证据**：实测 2026-09-27（UAT）；`plm-req.cjs` 常量 `SOURCE_TYPES` / `SOURCE_CHANNELS`；`check` 第 6 步。
- **教训（可迁移）**：**"看起来同义"的两个字段最危险**——不要凭语义猜值域，要么读元数据，要么让服务端先拒一次（代价小）。

## L-002 复用别人的 headless 浏览器会静默挂死（"端口在" ≠ "能用"）

- **症状**：`login` 打印"打开 …触发 SSO…"后**永久无输出**（不是报错，是挂住——比报错更贵，会被误读为"还在跑"）。
- **成因**：`:9222` 常驻另一个 harness 起的 headless Chrome，**没带 `--ignore-certificate-errors`**；UAT 是自签证书 ⇒ 停在证书拦截页，headless 无人可点"继续" ⇒ 等登录表单无限等待。
- **修复**：只在**自己启动的**实例上工作（外部实例一律不复用），改在专用端口 9334 自起；复用判据从"端口可达"升级为"本工具所有"。
- **证据**：实测 2026-09-27（对比：自起实例 25s 内登录成功）。
- **教训**：**复用前要验证"能力"而不是"存在"**——这一条对一切"复用现成资源"的决策都成立。

## L-003 `Page.navigate` resolve ≠ 页面已到位（在错误的时机做点位判定）

- **症状**：偶发地跳过登录表单填充，最后报"等待 token 超时"，错误信息指向 token，与真因无关。
- **成因**：导航在 nginx 返回首页时就 resolve，首页 JS 稍后才 302 到 Keycloak。此时读 `location.href` 看到"还在应用站点" ⇒ 误判"已是登录态"。
- **修复**：**先等站点切走（进入 `/realms/`）或登录表单出现**，再决定要不要填表；并在超时信息里带上"是否已提交登录表单"以区分两种失败。
- **证据**：实测 2026-09-27；`plm-sso.cjs` `ssoLogin` 内注释。
- **教训**：**异步导航后的第一个判断点，必须建立在"目标条件已出现"上，而不是"导航调用已返回"上。**

## L-004 别用 PowerShell 管道"重写"含中文的 Markdown（会把整篇压成一行）

- **症状**：`(Get-Content $p) | Where-Object {...} | Set-Content $p` 之后，文件从 30 行变成 **1 行**——所有换行消失，正文被空格拼成一大段（中文照旧可读，所以**很难一眼看出坏了**，直到有人去 grep 某个章节才发现）。
- **成因**：PowerShell 的 `Get-Content` 默认把文件读成**字符串数组**，但经 `Where-Object`/`ForEach-Object` 等管道后，`Set-Content` 收到的常被折叠/重排；配合 `-NoNewline` 更彻底 ⇒ 行结构丢失。**这是 PowerShell 的对象管道语义与"文本流"直觉不一致导致的**，不是编码问题（编码看起来是对的）。
- **修复**：**改文件内容一律用文件工具（`edit`/`write`），不要用 PowerShell 往返重写**。若必须用脚本批处理，用 Node（`fs.readFileSync`/`writeFileSync`）而不是 `Get-Content | Set-Content`。
- **证据**：实测 2026-09-27（本 skill 交付过程中真实踩到：一次"清理测试行"的操作把 `plm-lessons.md` 压成一行）。
- **教训（可迁移）**：**"看起来对"的文本比报错的文本更危险**——二进制/编码问题会立刻炸，**行结构丢失不会**。凡"原地重写文本"，都要在写完后复查行数与尾部内容。

## L-005 前缀纪律不是"命名风格"：台账文件漏了 `plm-` 前缀，后果是双向的

- **症状**：首次登记成功、终端打印"已记账"，但 `plm-kb.cjs query` 检索不到这条记录，`doctor` 也报"台账尚未生成"。
- **成因**：`appendLedger` 初版把台账写成 `registration-ledger.md`（**无 `plm-` 前缀**）。而 `.creature/kb/` 是**多 creature 共用家园**，交付型实例在这里有同名文件 ⇒ ① 两个 creature 的台账互相挤占/混写；② 本 skill 的检索只认 `plm-` 前缀 ⇒ **自己写的台账自己看不见**。
- **修复**：文件名改为 `plm-registration-ledger.md`，并把已有内容**迁移过去**（不重打、不丢历史）。同时把这条写进 `plm-conventions.md` 的命名纪律。
- **证据**：实测 2026-09-27；`plm-req.cjs` 的 `ledgerPath()` 注释。
- **教训（可迁移）**：**域隔离要靠物理屏障（文件名/目录），不能靠约定俗成**——"我记得带前缀"不是屏障，"检索只认前缀 + 文件名带前缀"才是。**漏前缀的后果不是"文件放错地方"，是"体系自我不可见"。**

## L-006 自检判据要锚"内容特征"，不要锚"格式细节"——否则自检会否认系统刚做过的事

- **症状**：登记成功、终端明确打印"已记账"、台账文件里也确实有那一行；但 `doctor` 报 **"登记台账：0 条"** ⇒ 看起来像"记账失败了"，而实际是**自检写错了**。
- **成因**：判据写成 `^\|\s*REQ-`（"行首竖线后紧跟编号"），而台账的**第一列是登记时间**，编号在**第二列** ⇒ 恒不命中。同类错误在本次交付里出现了三次（`|\s{4,}` 嫌空格少、`^\|\s*REQ-` 锚错列、`-match` 的数组语义），**全都是"判据与真实数据结构不一致"**。
- **修复**：判据改为按**内容特征**识别——`/^\|/.test(l) && /REQ-\d{4}-\d+/.test(l)`（行是表格行 **且** 含编号形态），不关心它在第几列。
- **证据**：实测 2026-09-27；`plm-kb.cjs` `cmdDoctor` 内注释。
- **教训（可迁移）**：**自检代码本身也会撒谎**——而"系统否认自己刚做过的事"比"系统没做"更糟：它让人去修一个没坏的东西。**凡自检失败，先验证自检的判据，再怀疑被检查的对象。**
